# Hermes Agent (Nous Research) — harness study for Goliath

Researched 2026-09-02 from the DeepWiki, the official docs site, the GitHub README, issue #15176, and the raw source files on `main`. Every claim carries its URL. Where two sources disagree (DeepWiki snapshots lag the code), both numbers are given and the one from the official docs or source is marked.

Goliath context, for reference while reading: Apple on-device ~3B model, 4,096-token window, one request in flight, guided JSON output, no logprobs; conductor plans one flat JSON step, a fresh-context worker returns tool arguments as structured output, Goliath runs the tool, results are compressed to `key: value` lines, writes confirm first, repeated call / empty answer / malformed plan (after one retry) / model error escalate to cloud with the step log, and a scribe keeps a 60-word brief with Goal/Done/Decisions/Next slots.

---

## 1. What it is, in 5 lines

1. A Python, single-process, "self-improving" general agent from Nous Research that runs on any OpenAI-compatible model (Nous Portal, OpenRouter, OpenAI, Anthropic, local Ollama/vLLM/llama.cpp) — https://github.com/NousResearch/hermes-agent
2. One `AIAgent` class (`run_agent.py`) is instantiated by every surface: CLI/TUI, a messaging gateway (Telegram, Discord, Slack, WhatsApp, Signal, email), an ACP server for editors, a web dashboard, cron jobs, and a batch runner — https://deepwiki.com/NousResearch/hermes-agent
3. A registry of 70+ tools in ~28 toolsets (terminal across 7 sandbox backends, files, browser, vision, web, MCP, `delegate_task` subagents, `execute_code` RPC) — https://hermes-agent.nousresearch.com/docs/developer-guide/architecture
4. A "learning loop": bounded `MEMORY.md`/`USER.md`, agent-authored `SKILL.md` skills with progressive disclosure, a background review fork after each turn, and a curator that archives/merges skills — https://hermes-agent.nousresearch.com/docs/user-guide/features/skills
5. Context is managed by a `ContextCompressor` that prunes old tool results deterministically, then has an auxiliary model write a 13-section structured handoff summary; provider failover exists for transport errors only, and progress-based local→cloud escalation was explicitly declined (#15176) — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching, https://github.com/NousResearch/hermes-agent/issues/15176

## 2. The main loop

**Turn phases.** `AIAgent.run_conversation()` drives `agent/conversation_loop.py` through: (1) turn prologue — `build_turn_context` assembles system prompt and messages; (2) context management — compression if over threshold; (3) LLM call with interruptible streaming; (4) response parsing — reasoning blocks and tool-call requests; (5) tool execution, sequential or concurrent; (6) `finalize_turn` — persist and housekeeping — https://deepwiki.com/NousResearch/hermes-agent/4.1-conversation-loop

**Iteration bound.** The inner loop is _unbounded by default_: `max_iterations = sys.maxsize` in source and `agent.max_turns: none` in config; the loop ends on stop conditions, not a count — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py, https://hermes-agent.nousresearch.com/docs/user-guide/configuration. The constructor exposes `max_iterations` and `iteration_budget` for callers that want a cap — https://deepwiki.com/NousResearch/hermes-agent/4-core-agent

**Stop conditions** (source): model returns no tool calls; `finish_reason` is terminal; the empty-response guard exhausts its recovery attempts; a non-retryable API error; compression attempts exceed their limit; the run budget times out — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Wall-clock budget.** With `agent.run_budget_seconds` set, at 80% elapsed the loop injects `RUN_BUDGET_WRAPUP_NOTICE` ("[SYSTEM NOTICE — run time budget nearly exhausted] …") — appended to the _newest tool message_, not the system prompt, to keep the prompt-cache prefix stable — https://deepwiki.com/NousResearch/hermes-agent/4.2-context-and-prompt-management, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Tool execution and result return.** `agent/tool_executor.py` dispatches sequentially or concurrently with `_MAX_TOOL_WORKERS = 8`; results are appended as `role: "tool"` messages carrying the original `tool_call_id`; after all results are collected, `enforce_turn_budget()` applies the per-turn aggregate cap — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Empty / degenerate responses.** After tools ran but the model returned nothing: `_EMPTY_TOOL_RESPONSE_NUDGE` = "You just executed tool calls but returned an empty response. Please process the tool results above and continue with the task." A reasoning-only response (Codex/Responses API) gets `_CODEX_INCOMPLETE_NUDGE` ("Your previous response contained only internal reasoning and never produced a visible answer or tool call…"). Retry counters tracked per turn: `codex_ack_continuations`, `length_continue_retries`, `truncated_tool_call_retries`, `compression_attempts` — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Repetition guard.** `is_repetition_dominated(text)` (`agent/repetition_guard.py`): fragments under 400 chars fail open; otherwise flag if normalised duplicate lines cover ≥50% of the fragment, or a 60-char exact substring repeats ≥5 times. When true the turn _aborts with a user-facing error_ instead of sending a continuation nudge (which would amplify the loop) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/repetition_guard.py

**Outer-loop error ceiling.** `_MAX_OUTER_LOOP_ERRORS = 8` exceptions per turn before abandonment, "preventing infinite retry loops on deterministic local failures"; transient API errors use `adaptive_rate_limit_backoff()` and `jittered_backoff()`; `agent.api_max_retries: 3` before provider fallback — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py, https://hermes-agent.nousresearch.com/docs/user-guide/configuration

**Streaming and interrupts.** Streaming is interruptible; a user correction mid-stream inserts the scaffold marker "[This response was interrupted by a user correction.]" and `close_interrupted_tool_sequence` repairs the message sequence so the transcript stays valid — https://deepwiki.com/NousResearch/hermes-agent/4.1-conversation-loop, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py. In the CLI, Ctrl+C or slash commands with `busy_policy="interrupt_then_dispatch"` (e.g. `/stop`, `/new`) interrupt a running agent — https://deepwiki.com/NousResearch/hermes-agent/3.1-interactive-chat

**Verification nudges.** `agent.verify_guidance: true`, `agent.max_verify_nudges: 3`, optional `verify_on_stop` for code edits — https://hermes-agent.nousresearch.com/docs/user-guide/configuration

## 3. Context management

**Trigger.** `ContextCompressor.should_compress(prompt_tokens)` fires when prompt tokens (taken from the API's `usage`, via `update_from_response`) reach `threshold × context_length`. Official default `compression.threshold: 0.50`; models under `_SMALL_CTX_WINDOW_LIMIT = 512,000` are floored (raise-only) to `_SMALL_CTX_THRESHOLD_PERCENT = 0.75`. So for any small model the effective trigger is 75% — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py. (DeepWiki quotes 0.75 as the `threshold_percent` default in `context_engine.py` — https://deepwiki.com/NousResearch/hermes-agent/10.1-context-compression.) A second, fixed 85% "gateway session hygiene" threshold is a safety net in front of the agent; intermediate warnings were removed — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching. Context length is resolved from models.dev → family defaults → local probes (Ollama `/api/show`) → `parse_context_limit_from_error()` on failure; tokens are estimated at ~4 chars/token, images ~1,500 tokens — https://deepwiki.com/NousResearch/hermes-agent/2.4-model-selection

**Protected head and tail.** `protect_first_n: 3` (system prompt + first exchange, hardcoded) and `protect_last_n: 20` (docs) — DeepWiki's snapshot says 6 — https://hermes-agent.nousresearch.com/docs/user-guide/configuration, https://deepwiki.com/NousResearch/hermes-agent/10.1-context-compression. In `tail_mode: lean` the tail is token-budgeted rather than counted: `tail_token_budget = threshold_tokens × target_ratio (0.20)`, soft ceiling 1.5×, minimum tail 3 messages, walking backward and aligning to tool-call/result group boundaries; `LEAN_TAIL_FLOOR_TOKENS = 10,000`, `LEAN_TAIL_CAP_TOKENS = 25,000`, `min_tail_user_messages: 1` — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py, https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/

**Phase 1: deterministic pruning before any LLM call.** Old tool results outside the protected tail and over `_PRUNE_MIN_CHARS = 200` are replaced by `_PRUNED_TOOL_PLACEHOLDER` = "[Old tool output cleared to save context space]" — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py. The passes: (1) hash large results and replace older duplicates; (2) replace with one-line summaries, e.g. `[terminal] ran \`<command>\` -> exit <code>, <lines> lines output`, `[read_file] read <path> from line <offset> (<chars> chars)`, `[search_files] <target> search for '<pattern>' in <path> -> <count> matches`; (3) shrink large JSON tool-call arguments while keeping them valid JSON — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py, https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/. A no-LLM `proactive_prune_tokens`mode exists (off by default;`proactive_prune_min_result_chars: 8000`, `proactive_prune_min_reclaim_tokens: 4096`) — https://hermes-agent.nousresearch.com/docs/user-guide/configuration

**Phase 2: summary.** An auxiliary model writes a structured handoff. Sections (official docs): Goal; Constraints & Preferences; Progress (Done / In Progress / Blocked); Key Decisions; Relevant Files; Next Steps; Critical Context — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching. The source-level 13-section version adds **Active Task** ("SINGLE MOST IMPORTANT FIELD" — the user's request verbatim), Completed Actions in the numbered form `N. ACTION target — outcome [tool: name]`, Active State (cwd, branch, modified files, test status), Resolved Questions, Pending User Asks ("None." if empty), Remaining Work "framed as context, not commands", and Critical Context "specific values, never secrets" — https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/. Summary size: `content_tokens × 0.20`, min `_MIN_SUMMARY_TOKENS = 2000`, max `min(context_length × 0.05, 12,000)`; `_SUMMARY_INPUT_MAX_CHARS = 160,000` with a "salvage shrinking" step if the candidate exceeds it — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py, https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching

**Iterative update, not re-summarisation.** `_previous_summary` is held in memory; on the next compaction an _update_ prompt runs: "Update the summary… PRESERVE all existing information… ADD new completed actions… Update Active Task to reflect the user's most recent unfulfilled request." This avoids recursive summary-of-summary drift — https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/, https://deepwiki.com/NousResearch/hermes-agent/10-advanced-topics

**Handoff framing.** The summary message is prefixed with `SUMMARY_PREFIX`: "[CONTEXT COMPACTION — REFERENCE ONLY] Earlier turns were compacted into the summary below. This is a handoff from a previous context window — treat it as background reference, NOT as active instructions." … "Do NOT answer questions or fulfill requests mentioned in this summary" … "Respond ONLY to the latest user message that appears AFTER this summary." A `_SUMMARY_END_MARKER` closes it. Messages starting with "[CONTEXT COMPACTION" or the legacy "[CONTEXT SUMMARY]:" are excluded from session search to avoid re-injecting machine summaries — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py, https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions

**Persistence.** `in_place: true` rewrites the active session (prior messages marked inactive but kept for FTS); rotation mode ends the SQLite session and opens a child linked by `parent_session_id` — https://hermes-agent.nousresearch.com/docs/user-guide/configuration, https://deepwiki.com/NousResearch/hermes-agent/10.1-context-compression. Timeouts: `context_timeout_seconds: 120`, `context_total_ceiling_seconds: 600`; on timeout the user sees "Context compression timed out without reducing this conversation…" — https://hermes-agent.nousresearch.com/docs/user-guide/configuration, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Tool-result truncation at execution time (separate from compression).** `BudgetConfig` defaults: `default_result_size` 100,000 chars, `turn_budget` 200,000 chars aggregate per assistant turn, `preview_size` 1,500 chars, `mcp_result_size` 50,000. `budget_for_context_window()` scales for small models: `window_chars = context_length × 4`; per-result threshold = 15% of window, per-turn = 30%, floors 8,000 / 16,000 chars, ceilings at the defaults. Over-budget results are spilled to disk and replaced with a `<persisted-output>` preview stub whose path `extract_persisted_path()` can recover — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/budget_config.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py. Terminal output cap `tool_output.max_bytes: 50000`, `max_lines: 2000`, `max_line_length: 2000`; `file_read_max_chars: 100000`; `execute_code` stdout `MAX_STDOUT_BYTES` 50 KB spilled to `cache/exec/`; MCP hard cap 2,000,000 chars — https://hermes-agent.nousresearch.com/docs/user-guide/configuration, https://deepwiki.com/NousResearch/hermes-agent/5.6-code-execution-and-mcp-tools

**Caching.** Anthropic "system_and_3": breakpoint 1 = system prompt, 2–4 = rolling three most recent non-system messages; `prompt_caching.cache_ttl: "1h"` or `"5m"`. Rule: never mutate the system prompt mid-conversation; compression appends a note to it only on the first compaction; memory is a frozen snapshot; dynamic notices go on the newest tool message — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching, https://deepwiki.com/NousResearch/hermes-agent/4.2-context-and-prompt-management. `hermes prompt-size` reports the fixed per-call cost (system prompt + skills index + memory + tool schemas) offline — https://hermes-agent.nousresearch.com/docs/reference/faq

**Pluggable engine.** `ContextEngine` ABC: `name`, `update_from_response(usage)`, `should_compress(prompt_tokens)`, `compress(messages, current_tokens, focus_topic)`, optional `select_context()`, `on_turn_complete()`, session lifecycle hooks, `get_tool_schemas()`/`handle_tool_call()`; selected by `context.engine`, never auto-activated — https://hermes-agent.nousresearch.com/docs/developer-guide/context-engine-plugin

## 4. Tools

**Definition.** Tools self-register at import via `registry.register()` in `tools/registry.py`. A `ToolEntry` has `name`, `toolset`, `schema` (OpenAI function-calling JSON Schema), `handler(args: dict, **kwargs) -> str` (sync or async), `check_fn` (runtime availability: keys, deps, platform), `requires_env`, `is_async`, `description`, `emoji`, and `max_result_size_chars` — https://deepwiki.com/NousResearch/hermes-agent/5.1-tool-registry-and-toolsets, https://deepwiki.com/NousResearch/hermes-agent/5-tool-system

**Count and grouping.** 70+ tools across ~28 toolsets; toolsets are named lists with recursive `includes` (`web`, `terminal`, `file`, `browser`, `vision`, `image_gen`, `skills`, `todo`, `memory`, `session_search`, `cronjob`, `code_execution`, `delegation`, `clarify`, `messaging`, `safe`, `mcp-<server>` …). Per-platform defaults live under `platform_toolsets`; niche sets (`video_gen`, `x_search`) are off until credentials appear — https://hermes-agent.nousresearch.com/docs/developer-guide/architecture, https://hermes-agent.nousresearch.com/docs/user-guide/features/tools, https://deepwiki.com/NousResearch/hermes-agent/5.1-tool-registry-and-toolsets

**Deferred loading.** Discovery AST-scans `tools/` for `registry.register` calls and caches verdicts in `tool_discovery_cache.json` keyed by mtime+size; `check_fn`s run once per `get_definitions()`. There is no per-turn lazy schema loading — the whole enabled set is sent every call (hence `hermes prompt-size`) — https://deepwiki.com/NousResearch/hermes-agent/5.1-tool-registry-and-toolsets, https://hermes-agent.nousresearch.com/docs/guides/tips

**Description style.** "Concise, function-oriented, and emphasize practical use cases rather than technical implementation details" — https://hermes-agent.nousresearch.com/docs/user-guide/features/tools. System-prompt guidance blocks: `TOOL_USE_ENFORCEMENT_GUIDANCE` ("You MUST use your tools to take action — do not describe what you would do or plan to do without actually doing it."), `PARALLEL_TOOL_CALL_GUIDANCE` ("When you need several pieces of information that don't depend on each other, request them together in a single response…"), plus `OPENAI_MODEL_EXECUTION_GUIDANCE` for tool persistence and mandatory tool use for arithmetic/hashing — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/prompt_builder.py

**Validation.** `_parse_tool_arguments()` is plain `json.loads`; if it fails or isn't a dict the tool is _not run_ and the model gets "Tool arguments must be a valid JSON object; tool was not executed." A separate `_repair_tool_call_arguments()` in the loop attempts JSON repair on the exception path — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py

**Result formatting.** Handlers return strings; errors are wrapped as JSON `{"error": "<message>"}` via `tool_error()` (auto-truncated); the generic form is `Error executing tool '<name>': <err>` or `timed out after <n>s`. Result size obeys `max_result_size_chars` then `BudgetConfig` (§3) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py, https://deepwiki.com/NousResearch/hermes-agent/5.1-tool-registry-and-toolsets

**Programmatic tool calling.** `execute_code` runs Python in the sandbox with a generated `hermes_tools.py` stub that RPCs back (Unix socket locally; file polling for Docker/SSH), allowlisted to `web_search`, `web_extract`, `read_file`, `write_file`, `search_files`, `patch`, `terminal`; 50 tool calls per script — https://deepwiki.com/NousResearch/hermes-agent/5.6-code-execution-and-mcp-tools, https://deepwiki.com/NousResearch/hermes-agent/5.2-terminal-and-file-operations

**MCP.** Servers under `mcp_servers`; tools namespaced `mcp__{server}__{tool}`; stdio/HTTP/SSE; 5 reconnects with exponential backoff — https://deepwiki.com/NousResearch/hermes-agent/5.6-code-execution-and-mcp-tools

## 5. Subagents / delegation

**Tool shape.** `delegate_task` takes `goal` (required), `context`, `toolsets`, `model`, `background`, plus a control plane `action` (`spawn`/`list`/`steer`/`stop`), `subagent_id`, `message`; batch mode takes a `tasks` list. The schema is built dynamically to reflect the configured concurrency and depth — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py, https://deepwiki.com/NousResearch/hermes-agent/5.7-subagent-delegation

**Isolation.** Fresh conversation (no parent history unless passed in `context`), unique `task_id` (own terminal session and file caches), a purpose-built system prompt (goal, context, workspace path, project context files, "completion instructions emphasizing concise summaries"), optional git worktree at `.worktrees/subagent-<id>` — https://deepwiki.com/NousResearch/hermes-agent/5.7-subagent-delegation, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py

**Blocked in children.** `delegate_task`, `clarify` (would deadlock the TUI), `memory` (conflicting writes to the parent's MEMORY.md), `send_message`, `cronjob_manage`, and the `delegation`/`kanban` toolsets; `role="orchestrator"` regains `delegate_task` within depth — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py

**Limits.** `delegation.max_spawn_depth` default 1; `max_concurrent_children` default 10 in source (DeepWiki snapshot says 3), floor 1; child `DEFAULT_MAX_ITERATIONS = 250`; `child_timeout_seconds` off by default (floor 30 s); heartbeat 30 s; stale-idle 450 s (15 cycles), stale-in-tool 1200 s (40 cycles) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py, https://deepwiki.com/NousResearch/hermes-agent/5.7-subagent-delegation

**Outputs.** Child returns `status` (success/failed/error/timeout), `summary` (capped by `_apply_summary_budget`, hard ceiling `DEFAULT_MAX_SUMMARY_CHARS` 24,000), `tool_trace` (metadata only: `tool_name`, sanitised `tool_input` + targets, `input_bytes`, `output_bytes`, `status`; URLs stripped of credentials, paths ≤1,024 chars, ≤64 arg keys), `missed_steer`, and an output tail of the last 12 tool results with previews (≤8,000 chars) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py

**Structured output.** A caller-supplied JSON Schema is appended with: "Your FINAL response must be a single JSON object that validates against this JSON Schema." "No prose before or after the JSON; a ```json code fence is acceptable but not required." On validation failure: best-effort JSON extraction, then **exactly one** retry (`MAX_SCHEMA_RETRIES = 1`) listing up to 10 "Validation errors" without re-pasting the schema, because "frontier models drop fields that were right the first time" on repeated attempts — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegation_output_schema.py

**Approvals in children.** `_subagent_auto_deny` by default; `delegation.subagent_auto_approve: true` for batch/cron; a global `_spawn_paused` flag halts spawning — https://deepwiki.com/NousResearch/hermes-agent/5.7-subagent-delegation

**Async mode.** `background=true` returns a `delegation_id`; completion events land in `process_registry.completion_queue` as synthetic turns and persist in `state.db`; a `subagent_stop` hook fires with role, status, summary, duration — https://deepwiki.com/NousResearch/hermes-agent/5.7-subagent-delegation

## 6. Memory and self-improvement

**Files and budgets.** `~/.hermes/memories/MEMORY.md` — 2,200 chars (~800 tokens): environment facts, conventions, lessons. `USER.md` — 1,375 chars (~500 tokens): preferences and communication style. Entries are `§`-delimited multiline blocks. Tool actions `add`, `replace`, `remove` by short unique substring; batch operations in one call with the limit checked only on the final result — https://hermes-agent.nousresearch.com/docs/user-guide/features/memory, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/memory_tool.py

**Tool description to the model.** "Save durable facts to persistent memory that survive across sessions. Memory is injected into every future turn, so keep entries compact and high-signal." Save-priority: (1) user preferences and corrections, (2) environment facts, (3) procedures. Do not save trivia, re-discoverable facts, raw dumps, task progress, temporary TODO state, or procedures that belong in skills — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/memory_tool.py

**Capacity-exceeded reply.** "Memory at X/Y chars. Adding this entry (Z chars) would exceed the limit. Consolidate now: use 'replace' to merge overlapping entries into shorter ones or 'remove' stale or less important entries…, then retry this add — all in this turn." Docs advise consolidating past 80% — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/memory_tool.py, https://hermes-agent.nousresearch.com/docs/user-guide/features/memory

**Injection.** Frozen-snapshot pattern: loaded at session start, threat-scanned, stored as `_system_prompt_snapshot`, never mutated mid-session (cache stability); writes go to disk with advisory locks; drift detection on external edits creates a `.bak` and rejects the write — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions. Prompt guidance: "You have persistent memory, carried across sessions and loaded into each new session's context; the memory tool's schema defines what belongs there." — write declarative facts, route by longevity (stale-within-a-week → session history; procedures → skills) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/prompt_builder.py

**Skills.** Directories with `SKILL.md` (agentskills.io frontmatter: `name` ≤64 chars, `description` ≤1,024, `platforms`, `metadata.hermes.{tags,category,requires_toolsets,config}`; body sections "When to Use / Procedure / Pitfalls / Verification"). Progressive disclosure: level 0 index in the system prompt (~3k tokens for names + truncated descriptions), level 1 `skill_view(name)`, level 2 `skill_view(name, path)` — https://hermes-agent.nousresearch.com/docs/user-guide/features/skills, https://deepwiki.com/NousResearch/hermes-agent/8-skills-system

**Auto-creation.** Prompt nudge: "When you work out a non-trivial workflow, record it with skill_manage for future reuse." Triggers named in docs: worked out a multi-step workflow worth repeating; hit errors and found the working path; user corrected the approach. Tips page: 5+ steps = skill candidate; memory for facts, skills for procedures — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/prompt_builder.py, https://hermes-agent.nousresearch.com/docs/user-guide/features/skills, https://hermes-agent.nousresearch.com/docs/guides/tips. `skill_manage` actions: `create`, `edit`, `patch` (preferred), `delete`, `write_file`, `remove_file` — https://hermes-agent.nousresearch.com/docs/user-guide/features/skills

**Background review.** After each turn `spawn_background_review()` forks a restricted agent on a daemon thread that replays the conversation and decides whether a memory or skill should change, cancelled by `_BackgroundReviewRun` if a new foreground turn starts; carries `_review_input_token_budget`. A curator (`maybe_run_curator()`, `apply_automatic_transitions()`) runs when idle to archive inactive skills and merge overlapping ones — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions, https://deepwiki.com/NousResearch/hermes-agent/8-skills-system. `memory.write_approval` / `skills.write_approval` stage these writes under `~/.hermes/pending/` for `/skills approve` — https://hermes-agent.nousresearch.com/docs/user-guide/features/skills

**Sessions.** SQLite WAL, FTS5 `messages_fts`; `session_search` modes DISCOVERY (±5 messages), SCROLL, READ, BROWSE; kanban/subagent/tool sessions hidden, cron demoted; gateway 1-hour auto-continue freshness window — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions

## 7. Permissions and approvals

- Three detection layers: hardline blocklist (`rm -rf /`, fork bombs, formatting mounted devices, untrusted URL piped to root shell — never overridable, even in YOLO); gateway lifecycle guard (blocks restart-loop attacks on the gateway itself); regex patterns (recursive/force `rm` in any flag order, Windows `del /f /q`, `Remove-Item -Recurse -Force`) — https://deepwiki.com/NousResearch/hermes-agent/5.4-security-and-command-approval, https://hermes-agent.nousresearch.com/docs/user-guide/security/
- CLI prompt offers **once / session / always / deny** (deny is default); "always" persists the pattern to `command_allowlist` in `config.yaml` — https://hermes-agent.nousresearch.com/docs/user-guide/security/
- `approvals.mode`: `smart` (default — auxiliary model risk-assesses; low-risk auto-approve, high-risk auto-deny, uncertain → prompt), `manual`, `off` (= `--yolo`) — https://hermes-agent.nousresearch.com/docs/user-guide/security/
- Over chat the agent posts the command and waits for yes/approve/ok/go or no/deny/cancel; headless `approvals.cron_mode` and `approvals.single_query_mode` default to `deny` — https://hermes-agent.nousresearch.com/docs/user-guide/security/
- Tirith external scanner: exit 0 allow / 1 block / 2 warn; circuit breaker after 3 consecutive failures; configurable fail-open — https://deepwiki.com/NousResearch/hermes-agent/5.4-security-and-command-approval
- Env sanitisation strips provider keys from child processes; write denylist for SSH keys, `.netrc`, `.aws/credentials`, device paths — https://deepwiki.com/NousResearch/hermes-agent/5.2-terminal-and-file-operations
- Memory and skill writes can each be gated (`memory.write_approval`, `skills.write_approval`); computer-use mutating actions require approval; skills guard trust levels builtin/trusted/community/agent-created — https://hermes-agent.nousresearch.com/docs/user-guide/configuration, https://deepwiki.com/NousResearch/hermes-agent/5.4-security-and-command-approval

## 8. Hooks / extensibility

- Four middleware kinds: `llm_request` (rewrite messages/tools), `llm_execution` (wrap the network call), `tool_request` (rewrite args), `tool_execution` (wrap the handler); registered in a plugin's `register(ctx)`; run in registration order, later sources override; errors caught and logged — https://deepwiki.com/NousResearch/hermes-agent/10.11-middleware-system
- Shell hooks (`shell_hooks.py`) at `pre_tool_call` / `post_tool_call` read JSON on stdin and reply `{"decision": "block", "reason": "..."}` or `{"action": "modify", "args": {...}}`; `fail_closed: true` for security-critical hooks — https://deepwiki.com/NousResearch/hermes-agent/10.11-middleware-system
- `subagent_stop` hook (§5); context-engine plugins (§3); memory-provider plugins (Honcho, Mem0, Hindsight …); MCP for tools; A2A protocol with HMAC signing — https://deepwiki.com/NousResearch/hermes-agent/10-advanced-topics, https://hermes-agent.nousresearch.com/docs/user-guide/features/memory

## 9. Error handling and recovery

**API-level.** `classify_api_error()` decides: 402 payment → credential rotation / `_try_activate_fallback`; 429 → retry with backoff, respect `Retry-After`, 1-hour cooldown on the credential; 401 transient → 5-minute cooldown; context overflow → compression or fallback; `api_max_retries: 3` — https://deepwiki.com/NousResearch/hermes-agent/10.2-provider-runtime-resolution, https://hermes-agent.nousresearch.com/docs/user-guide/configuration

**Provider fallback (`fallback_providers`).** Ordered list of `{provider, model}`. Triggers: 429 and 5xx after retries; 401/403 and 404 immediately; repeated malformed/empty API responses. In-place swap of model/provider/client — "your conversation history, tool calls, and context are preserved" — but prompt caches are invalidated. **Turn-scoped**: the next user message tries the primary again — https://hermes-agent.nousresearch.com/docs/user-guide/features/fallback-providers

**Local→cloud on quality: declined.** Issue #15176 asked for `model_routing.fallback_policy` with `max_local_attempts: 3` and triggers `repeated_tool_failure`, `invalid_output`, `no_progress`, `task_timeout`, `user_request`, preserving context and logging the reason. Closed 2026-07-12 as not-planned under the standing `delegation-model-routing` policy: "The policy explicitly rejects model tiers and complexity-based automatic routing"; `fallback_providers` is for "concrete provider/API failures" only — https://github.com/NousResearch/hermes-agent/issues/15176. The most useful comment (Keesan12) splits the problem into _admission control_ ("should the local model get another turn?") and _escalation target_, warns that "the expensive failure mode is… 'local model keeps buying more attempts without new evidence'", and proposes: max consecutive no-progress turns, max repeated tool/result pattern, a local spend budget, and a "carry-forward receipt into the cloud handoff: last good state, last verifier result, halt reason" — https://github.com/NousResearch/hermes-agent/issues/15176

**Local-model signals Hermes does handle.** Auto-detects local endpoints and relaxes streaming (read timeout 120 s → 1800 s, stale-stream detection off); warns that Ollama `/api/show` reports _maximum_ not effective `num_ctx`; notes that models without tool-call support "can only chat", that raw-JSON-instead-of-tool-call is usually a server flag (`--jinja`, `--enable-auto-tool-choice --tool-call-parser hermes`), and that only `gemma4:31b` in its list has reliable tool calling; recommends `num_ctx 64000` as the minimum for agentic work — https://hermes-agent.nousresearch.com/docs/reference/faq, https://hermes-agent.nousresearch.com/docs/guides/local-ollama-setup

**Malformed tool input.** Not executed; model told "Tool arguments must be a valid JSON object; tool was not executed." plus `_repair_tool_call_arguments()` on the exception path (§4). Structured-output failures: one retry with listed errors (§5) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegation_output_schema.py

**Loop-level.** Empty-response nudge; repetition guard aborts the turn; `_MAX_OUTER_LOOP_ERRORS = 8`; run-budget wrap-up at 80% (§2) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/repetition_guard.py

## 10. Evals / testing

- pytest suite under `tests/` (ci, docker, gateway, plugins, tools) run by `tests.yml` on a 96-core runner with `uv sync --locked`; `lint.yml` runs ruff + ty; `supply-chain-audit.yml` scans `.pth` files and obfuscated payloads. "The content does not mention explicit evaluation benchmarks or performance metrics." — https://deepwiki.com/NousResearch/hermes-agent/14-infrastructure-and-cicd
- The batch runner (`batch_runner.py`) takes JSONL `{prompt, image?, cwd?}`, runs one isolated `AIAgent` per worker (`--num_workers`, default 4), writes ShareGPT-style `trajectories.jsonl` and `statistics.json` with per-tool calls/successes/failures and "percentage of assistant turns with reasoning"; samples lacking reasoning are discarded. Docs call it usable for "Model Evaluation… how well a model uses tools across standardized prompts", but define no scorer — https://hermes-agent.nousresearch.com/docs/user-guide/features/batch-processing
- `hermes doctor` (SQLite integrity, provider connectivity) and `hermes prompt-size` are the runtime diagnostics — https://deepwiki.com/NousResearch/hermes-agent/4-core-agent, https://hermes-agent.nousresearch.com/docs/reference/faq

## 11. What Goliath should borrow

Each item is concrete enough to become a test.

1. **Turn-scoped escalation.** When a turn escalates to cloud, only that turn runs on cloud; the next user message starts on-device again. Test: after a cloud-handled turn, the next turn's first request goes to the on-device provider — https://hermes-agent.nousresearch.com/docs/user-guide/features/fallback-providers
2. **Separate admission control from escalation target, and hand over a receipt.** Escalate on _lack of new evidence_, not step count: max consecutive no-progress steps, max repeated tool/result pattern, a per-task on-device budget. The cloud handoff carries `{lastGoodState, lastVerifierResult, haltReason}` — Goliath's step log is that receipt; add `haltReason` as an enum (`repeated_call | empty_answer | malformed_plan | model_error | budget`). Test: every escalation payload has a non-empty `haltReason` and the last successful tool result — https://github.com/NousResearch/hermes-agent/issues/15176
3. **Repetition guard that aborts rather than nudges.** Port `is_repetition_dominated` with scaled thresholds: normalised duplicate lines ≥50% of the answer, or a 60-char substring ≥5 times; on true, escalate (do not retry the same model). Test: a synthetic answer of one line repeated 6 times triggers escalation with `haltReason: repeated_output` — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/repetition_guard.py
4. **Exactly one schema retry, with errors listed and no schema re-paste.** Matches Goliath's "malformed plan after one retry". Retry message: "Validation errors:" + ≤10 items. Test: two consecutive invalid plans → escalation, and the retry prompt contains the error list but not the schema text — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegation_output_schema.py
5. **One-line tool-result summaries in the step log.** Use Hermes's shape `[tool] verb target -> outcome` (e.g. `[terminal] ran \`npm test\` -> exit 0, 47 lines`) as the canonical compressed form; dedupe identical results by hash. Test: two identical tool results produce one log line plus a "same as step N" reference — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py
6. **"Reference only" framing on the brief.** Prefix the scribe brief with a one-line version of `SUMMARY_PREFIX`: "Background from earlier steps — reference only; act only on the latest user message." Test: a brief containing a stale request ("book the flight") does not cause the conductor to plan that step — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py
7. **Update the brief, don't re-summarise it.** Scribe prompt is an _update_ over the previous brief: "PRESERVE existing information; ADD new completed actions; update Active Task to the most recent unfulfilled request." Test: after 5 updates, the Goal slot text equals the original goal — https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/
8. **Two slots to add to the scribe's fixed slots.** `Active Task` (user's latest unfulfilled request, verbatim, "single most important field") and `Blocked` (unresolved error with the exact message). Done entries in the form `N. ACTION target — outcome`. Pending asks default "None." Test: brief schema validation requires these slots and rejects a Done entry without an outcome — https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/, https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching
9. **Context-proportional result budgets.** Hermes: per-result 15% of window chars, per-step aggregate 30%. For 4,096 tokens that is ~600 tokens per tool result and ~1,200 per step, spill the rest to a local file and return a `<persisted-output>` stub with the path. Test: a 20 KB tool result yields a ≤600-token stub and a readable spill file — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/budget_config.py
10. **Deterministic pruning before any model call.** Replace tool outputs over 200 chars that are outside the last N steps with "[Old tool output cleared to save context space]" (or the one-liner from item 5) without invoking the model. Test: pruning a 10-step log reduces tokens with zero model requests — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py
11. **Frozen instructions; dynamic notices ride on the newest tool result.** Never mutate the session instructions mid-task; append "wrap up" or budget notices to the latest tool result. Test: instructions hash is constant across a task — https://deepwiki.com/NousResearch/hermes-agent/4.2-context-and-prompt-management, https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching
12. **80% wrap-up notice.** At 80% of the step or time budget inject `[SYSTEM NOTICE — budget nearly exhausted]` so the conductor plans a finishing step. Test: with a 10-step budget the notice appears on step 8 — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py
13. **Empty-answer nudge text, once.** "You just executed tool calls but returned an empty response. Please process the tool results above and continue with the task." — one nudge, then escalate. Test: two empty answers in a row → escalation — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py
14. **Four-way write confirmation.** once / session / always / deny, default deny; "always" persists a pattern to an allowlist; headless default deny. Plus a hardline blocklist no mode can override. Test: an "always"-approved pattern skips the prompt next session; a blocklisted action is refused under every mode — https://hermes-agent.nousresearch.com/docs/user-guide/security/
15. **Worker tool denylist.** Children never get delegation, clarify/ask-user, memory writes, messaging, or scheduling. In Goliath, workers get exactly one tool and never the confirm/memory/scribe tools. Test: worker tool set ∩ {confirm, memory, scribe} = ∅ — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py
16. **Step-log entry shape from the child `tool_trace`.** `{toolName, input (sanitised, ≤64 keys, paths ≤1,024 chars, credentials stripped from URLs), inputBytes, outputBytes, status}`. Test: a URL with a token in the query string is logged without the token — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py
17. **Memory write rules.** Save priority: preferences & corrections > environment facts > procedures; never save task progress or TODO state; declarative facts, not imperatives; capacity error returns usage and demands consolidation _in the same turn_. Test: an add over budget returns `at X/Y chars` and no write — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/memory_tool.py, https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/prompt_builder.py
18. **Memory as a frozen per-session snapshot.** Load once per task, write-through to disk, re-read next task. Test: a memory write mid-task does not change the current session's instructions — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions
19. **Fixed-cost prompt measurement.** A `prompt-size` check that asserts instructions + plan schema + tool description stay under a budget (say 900 tokens of 4,096). Test: CI fails if the fixed prefix exceeds the budget — https://hermes-agent.nousresearch.com/docs/reference/faq
20. **Error-classification table for the cloud client.** 429 → backoff and honour `Retry-After`; 5xx → retry then fail; 401/403/404 → fail immediately; malformed/empty response → count toward escalation. Test: a 404 produces no retries — https://hermes-agent.nousresearch.com/docs/user-guide/features/fallback-providers
21. **Bounded outer-loop error count.** `_MAX_OUTER_LOOP_ERRORS = 8` per turn; Goliath should use a smaller number (3) since each on-device error costs seconds. Test: the 4th model error in one turn escalates — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py
22. **Eval harness shape.** JSONL prompts → trajectories + `statistics.json` with per-tool calls/success/failure and a coverage metric; for Goliath add `escalationRate` and `stepsToDone`. Test: a fixture run produces those fields — https://hermes-agent.nousresearch.com/docs/user-guide/features/batch-processing
23. **Session freshness window.** Auto-continue a prior task only if the user returns within 1 hour; otherwise start fresh. Test: a resume after 61 minutes gets an empty brief — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions
24. **Token estimate fallback.** ~4 chars per token when the runtime does not report usage — https://deepwiki.com/NousResearch/hermes-agent/2.4-model-selection

## 12. What does not transfer to a 4k on-device model, and why

1. **The compression math.** Hermes's smallest design point is `_SMALL_CTX_WINDOW_LIMIT = 512,000`; min summary 2,000 tokens, tail floor 10,000, cap 25,000, summary input up to 160,000 chars. At 4,096 tokens the minimum summary alone is half the window. Goliath's 60-word brief is the right order of magnitude; only the _shape_ (items 5–8) transfers — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py
2. **Unbounded iterations.** `max_turns: none` / `sys.maxsize` relies on stop conditions and a 200k-token context to absorb wandering. Goliath needs a hard step budget — https://hermes-agent.nousresearch.com/docs/user-guide/configuration
3. **Whole tool set every call.** 70+ schemas, a ~3k-token skills index, and 2,200 + 1,375 chars of memory (~1,300 tokens) are sent on every request. That is a third of Goliath's window before any conversation. Goliath's one-tool-per-worker design is the opposite and correct; memory must be a few hundred chars, and a skills index only if it fits in ~150 tokens — https://hermes-agent.nousresearch.com/docs/developer-guide/architecture, https://hermes-agent.nousresearch.com/docs/user-guide/features/skills, https://hermes-agent.nousresearch.com/docs/user-guide/features/memory
4. **Parallel tool calls and 8 workers.** Apple's runtime allows one request in flight, and the 3B model is unlikely to emit reliable multi-call batches; `PARALLEL_TOOL_CALL_GUIDANCE` is moot — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/tool_executor.py
5. **An auxiliary model for side tasks.** Compression, smart approval, vision, and titles all go to a second (often cloud) model. On device there is one model and one slot; every scribe call blocks the conductor. Goliath's scribe must be short and rare, or run on the cloud fallback — https://deepwiki.com/NousResearch/hermes-agent/4.5-auxiliary-client
6. **Background review and curator.** They fork the agent and replay the _whole transcript_ in a daemon thread. There is no spare inference slot on device, and no transcript that fits. Skill/memory learning has to be an explicit, tiny, end-of-task step — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions
7. **Subagent sizing.** 250 iterations per child, 24,000-char summaries, last-12 tool results at 8,000 chars, 10 concurrent children — none fits. Goliath's fresh-context worker that returns only arguments is the 4k analogue — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/delegate_tool.py
8. **JSON repair of tool arguments.** `_repair_tool_call_arguments()` exists because free-text models emit broken JSON. Guided generation makes syntactic failures impossible; only semantic validation (wrong values, missing intent) remains, which is what item 4 in §11 covers — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/conversation_loop.py
9. **Provider chains and credential pools.** Six-deep auxiliary fallback, round-robin credentials, 402 rotation, cooldown tables — Goliath has exactly two providers (device, cloud). Only the error-classification table (item 20) transfers — https://deepwiki.com/NousResearch/hermes-agent/10.2-provider-runtime-resolution
10. **Prompt-cache breakpoints.** "system_and_3" is an Anthropic API feature. The transferable idea is the discipline (frozen instructions, notices on the newest message), not the mechanism — https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching
11. **Full-transcript session search.** FTS5 over every message with ±5-message windows returns raw text; the results alone would overflow 4k. Goliath can search, but must return one-line log entries — https://deepwiki.com/NousResearch/hermes-agent/4.3-memory-and-sessions
12. **Repetition-guard thresholds as written.** 400-char minimum fragment and a 60-char window assume verbose outputs; on-device answers are short, so the minimum needs to drop (≈120 chars) or the guard never fires — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/repetition_guard.py
13. **The `SUMMARY_PREFIX` verbatim.** It is several sentences; at 4k it must be one line (item 6) — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/context_compressor.py
14. **"You MUST use your tools" enforcement prose.** Written for frontier models that narrate instead of acting. A 3B model under guided output cannot narrate a tool call — the schema forces the action — so the prose is wasted tokens — https://raw.githubusercontent.com/NousResearch/hermes-agent/main/agent/prompt_builder.py
15. **Sandboxes, Tirith, Docker hardening, MCP.** Execution environments and external scanners assume a shell host; Goliath's tools are app APIs on a phone. The hardline-blocklist _concept_ (item 14) transfers; the machinery does not — https://deepwiki.com/NousResearch/hermes-agent/6-execution-environments
16. **Hermes's own position on local→cloud.** The maintainers reject progress-based routing as a design direction; Goliath is building exactly that, so Hermes offers the _arguments_ (issue thread) but no code path to copy — https://github.com/NousResearch/hermes-agent/issues/15176
