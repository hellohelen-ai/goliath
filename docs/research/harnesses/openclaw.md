# OpenClaw — harness research brief for Goliath

Researched 2026-09-02 from the DeepWiki (`https://deepwiki.com/openclaw/openclaw`, indexed at commit `87dc48`), the GitHub README, and the repo's own `docs/` and source where the wiki was vague on numbers. Every claim carries its URL. "Goliath" below means our on-device harness: ~3B Apple Foundation Model, 4,096-token window, one request in flight, guided JSON output, no logprobs, driven from React Native via the Vercel AI SDK.

---

## 1. What it is, in 5 lines

1. OpenClaw is "a multi-platform AI gateway and personal assistant system that orchestrates conversations between messaging channels and AI agents" — a local Node.js **Gateway** that is "the local control plane for sessions, tools, events, and channel connections" (https://deepwiki.com/openclaw/openclaw, https://github.com/openclaw/openclaw).
2. It meets users in WhatsApp, Telegram, Slack, Discord, Google Chat, Signal, iMessage, plus its own Control UI/CLI/TUI and native iOS/macOS/Android/Linux "nodes" (https://github.com/openclaw/openclaw).
3. The agent runtime is "built on Pi Agent Core with OpenClaw-specific extensions for sandboxing, memory, and failover", with Codex and external CLI backends (claude-cli, opencode) as alternates (https://deepwiki.com/openclaw/openclaw/3-agent-runtime).
4. Security is "trusted gateway, untrusted execution, deterministic policy" under a "personal assistant security model with a single trusted operator boundary per Gateway instance" (https://github.com/openclaw/openclaw, https://deepwiki.com/openclaw/openclaw/7.1-security-model-and-trust-boundaries).
5. It is a large, cloud-model-first system (389k stars, 87k commits, pnpm monorepo, Node 22+); its harness assumes 100k–200k-token windows, so most of its _numbers_ do not transfer, but many of its _shapes_ do (https://github.com/openclaw/openclaw, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/tool-result-limits.ts).

## 2. The main loop

**Turn flow (five stages).** (1) The `agent` RPC validates params, resolves the session, persists metadata and "immediately returns `{ runId, acceptedAt }`"; (2) `agentCommand` resolves the model, loads skills, calls `runEmbeddedAgent`, emits fallback lifecycle events; (3) `runEmbeddedAgent` "serializes runs per-session, builds the OpenClaw session, subscribes to runtime events, and enforces timeouts"; (4) `subscribeEmbeddedAgentSession` maps runtime events to streams — tools to `stream: "tool"`, deltas to `stream: "assistant"`, lifecycle to `stream: "lifecycle"`; (5) `agent.wait` polls and returns `{ status: ok|error|timeout, startedAt, endedAt, error? }` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md).

The wiki's seven-stage view of the same pipeline: Admission (`beginSessionWorkAdmission`) → Model resolution (`findModelInCatalog`, `resolveRunModelHasVision`) → Preparation (`prepareReplyRunContext`) → Execution (`runReplyAgent` → `runEmbeddedAgent`) → Tool dispatch (`resolveEffectiveToolPolicy`) → Attempt dispatch (`dispatchEmbeddedRunAttempt`, "manages prompt submission and heartbeat monitoring") → State (`persistSessionTranscriptTurn`) (https://deepwiki.com/openclaw/openclaw/3.1-execution-pipeline).

**Concurrency and write fencing.** "Runs serialize per-session key and optionally through a global lane. Before streaming, admitted runs record an `activeWriterRunId` claim. Every transcript append or rewrite supplies `expectedWriterRunId`," verified synchronously, so "superseded runs cannot commit stale transcript data" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md). A `lifecycleGeneration` version string invalidates stale runs across restarts and reloads (https://deepwiki.com/openclaw/openclaw/3-agent-runtime). New messages cancel the current turn via `createAgentRunSupersededAbortError` (https://deepwiki.com/openclaw/openclaw/3.1-execution-pipeline).

**Tool execution and result return.** Tool start/update/end events emit on the `tool` stream; "tool results are sanitized for size and image payloads before logging" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md). Each invocation carries an `executionIdentity` audit stamp (https://deepwiki.com/openclaw/openclaw/3-agent-runtime). A `ReplyTurnLedger` "tracks turn history to prevent infinite recursion" (https://deepwiki.com/openclaw/openclaw/3-agent-runtime).

**Step limits.** There is no per-turn tool-call cap documented. Limits are time-based: `agents.defaults.timeoutSeconds` default 172,800 s (48 h, `0` = unlimited); model idle 120 s (cloud) / 300 s (self-hosted); `agent.wait` 30 s (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md).

**Stop conditions.** "Where things can end early": agent timeout (abort), AbortSignal (cancel), Gateway disconnect, RPC timeout, `agent.wait` timeout (wait-only, does not stop the run) (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md). "Retryable errors receive a 15-second grace window before fallback or restart" (same URL).

**Streaming.** Two independent layers, "without true token-delta streaming": block streaming (completed blocks sent as channel messages, default `blockStreamingDefault: "off"`, boundary `text_end` or `message_end`) and preview streaming (editing a temporary message; modes `off|partial|block|progress`). Chunker rules: don't emit below `minChars`, prefer split before `maxChars`, break preference "paragraph → newline → sentence → whitespace → hard break", never split inside code fences. Preview chunk defaults `minChars: 200, maxChars: 800`; coalescing on Discord/Signal/Slack `{ minChars: 1500, idleMs: 1000 }`; channel `textChunkLimit` default 4000. Progress drafts: `maxLines: 8`, `maxLineChars: 120` word-aware, tool-progress lines like "searching the web" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/streaming.md).

**Interrupts / queueing.** Inbound messages during a run follow `messages.queue.mode`: `steer` (default — "inject messages into the active runtime", visible "before the next tool or model decision"), `followup` (separate turn after), `collect` (coalesce into one followup after the quiet window), `interrupt` (abort and run newest). Defaults: debounce 500 ms, `cap` 20 per session, `drop: "summarize"` (drop oldest but keep compact summaries as synthetic followup prompts; alternatives `old`, `new`). If steering is unavailable the prompt waits for the run to finish (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/queue.md). Inline directives `/think`, `/verbose`, `/reasoning`, and `NO_REPLY` ("Suppresses the assistant's response for a specific turn") are parsed during dispatch (https://deepwiki.com/openclaw/openclaw/3.5.2-status-and-directives).

## 3. Context management

**Trigger modes.** Compaction runs in three modes: "Token pressure (`budget`), Model errors (`overflow`), Manual commands (`/compact`)" (https://deepwiki.com/openclaw/openclaw/3.6-context-compaction). The budget trigger is "block on projected usage at or above the active model window minus the selected compaction reserve" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/reference/session-management-compaction.md). Defaults in agent-core: `{ enabled: true, reserveTokens: 16384, keepRecentTokens: 20000 }`; `MAX_COMPACTION_SUMMARY_CHARS = 16_000`; `IMAGE_BLOCK_TOKENS = 2_000` per image (https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts). The overflow path recognizes "dozens of provider-specific overflow strings (e.g., `context length exceeded`, `request_too_large`)" (https://deepwiki.com/openclaw/openclaw/3.6-context-compaction) and does "compact, then retry" rather than rotating sessions (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/reference/session-management-compaction.md).

**Cut-point algorithm.** `findCutPoint()` walks backward accumulating tokens, picks "the first valid cut point at or before the `keepRecentTokens` threshold", only user/assistant messages are valid boundaries ("Tool results are **not** valid cut points independently"), and if a turn must be split it records the turn start and summarizes the prefix with `TURN_PREFIX_SUMMARIZATION_PROMPT` ("This is the PREFIX of a turn that was too large to keep. The SUFFIX (recent work) is retained…") (https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts). "Tool call/result pairs stay together even exceeding chunk targets" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/compaction.md).

**Summary content.** The agent-core summarizer's system prompt: "You are a context summarization assistant. Your task is to read a conversation between a user and an AI assistant, then produce a structured summary following the exact format specified. Do NOT continue the conversation. Do NOT respond to any questions in the conversation. ONLY output the structured summary." The template asks for **Goal, Constraints & Preferences, Progress (Done / In Progress / Blocked), Key Decisions, Next Steps, Critical Context**, "preserve exact file paths and error messages". When a prior summary exists an UPDATE prompt "preserves existing information… moving completed items from 'In Progress' to 'Done'". Overlong summaries are capped with the marker `"\n\n[Compaction summary truncated to fit budget]"` (https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts).

OpenClaw's **safeguard** layer (`agents.defaults.compaction.mode: "safeguard"`, the default) adds five mandatory headings — `## Decisions`, `## Open TODOs`, `## Constraints/Rules`, `## Pending user asks`, `## Exact identifiers` — and re-distills a previous summary wrapped in `<previous-compaction-summary>` "rather than preserved verbatim" (https://deepwiki.com/openclaw/openclaw/3.6-context-compaction, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/compaction.md). Safeguard constants: `MAX_COMPACTION_SUMMARY_CHARS` 16,384; `MAX_RECENT_TURN_TEXT_CHARS` 600; `MAX_REQUIRED_ASK_CONTEXT_CHARS` 2,000; `MAX_TOOL_FAILURES` 8 at 240 chars each; `DEFAULT_RECENT_TURNS_PRESERVE` 3 (max 12); `DEFAULT_QUALITY_GUARD_MAX_RETRIES` 1 (max 3); `maxHistoryShare` 0.5; `maxChunkTokens = floor(contextWindow × adaptiveRatio) − SUMMARIZATION_OVERHEAD_TOKENS`; a 2,000-char `<workspace-critical-rules>` excerpt from AGENTS.md is carried into the summary. The re-distill prefix reads: "Previous compaction summary to re-distill with the current conversation. Prune stale, duplicate, or superseded details instead of preserving it verbatim." `auditSummaryQuality` checks "Missing required identifiers (extracted from last 10 messages)", "Absent latest user ask/request", "Unresolved user requests not preserved", "Missing workspace critical rules", and regenerates on failure (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts). Identifier policy is `strict` by default, `off` to disable (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/compaction.md). `/compact <focus>` text is "limited to 800 Unicode code points and escapes it as prompt data" (same URL). Omission markers total "at most 847 UTF-8 bytes per summarizer request" (same URL).

**Pre-compaction memory flush.** "Before compaction summarizes your conversation, OpenClaw runs a silent turn" so the agent writes notes to `memory/YYYY-MM-DD.md` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md). Threshold: `flushThreshold = compactionThreshold − softThresholdTokens`, `softThresholdTokens` default 4000, `forceFlushTranscriptBytes` 2 MB, `MAX_FLUSH_FAILURES = 3`, `TRANSCRIPT_OUTPUT_READ_BUFFER_TOKENS = 8192`, once per compaction cycle via `hasAlreadyFlushedForCurrentCompaction` (https://raw.githubusercontent.com/openclaw/openclaw/main/extensions/memory-core/src/flush-plan.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/src/auto-reply/reply/agent-runner-memory.ts). Default prompt: "Pre-compaction memory flush. Store durable memories only in memory/YYYY-MM-DD.md … If nothing to store, reply with [SILENT_REPLY_TOKEN]." (https://raw.githubusercontent.com/openclaw/openclaw/main/extensions/memory-core/src/flush-plan.ts).

**Tool-result truncation (live).** `DEFAULT_MAX_LIVE_TOOL_RESULT_CHARS = 16_000`, 32,000 for ≥100k-token windows, 64,000 for ≥200k; `MAX_TOOL_RESULT_CONTEXT_SHARE = 0.3` ("30% of context window tokens × 4" chars, capped); `maxContextChars` min 1,024 (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/tool-result-limits.ts). The truncator keeps `MIN_KEEP_CHARS = 2_000`, detects diagnostic tails with `error|exception|failed|fatal|traceback` and reserves "~30% of remaining budget to tail preservation", inserting `"\n\n⚠️ [... middle content omitted — showing head and tail ...]\n\n"`; aggregate budget `AGGREGATE_TOOL_RESULT_CONTEXT_SHARE = 0.5` with elision marker "[tool result elided: aggregate tool-result budget exceeded; rerun the command...]"; images cost `CACHE_TTL_IMAGE_CHARS = 8_000` and are replaced by "[image removed during context pruning]" (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/tool-result-truncation.ts). Exec stderr keeps a 64 KiB tail with the notice "[{droppedBytes} UTF-8 bytes of earlier stderr discarded…]" (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/sessions/tools/limits.ts). Persisted tool-result details are capped at 8,192 bytes / 2,000 chars per string (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/session-tool-result-guard.ts).

**Session pruning (between compactions).** Under `agents.defaults.contextPruning` (`mode: cache-ttl`, TTL 1h for Anthropic, `off` elsewhere): **soft-trim** — results over 4,000 chars "keep their first and last 1,500 characters with `...` in between"; **hard-clear** — when context usage reaches ~50% and ≥50,000 chars of prunable tool content remain, old results become `[Old tool result content cleared]`; "the last three assistant turns and everything before the session's first user message are never pruned" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/session-pruning.md).

**Overflow recovery order.** (1) truncate tool results if not yet tried, (2) auto-compact up to `MAX_OVERFLOW_COMPACTION_ATTEMPTS`, possibly rotating to a successor session, (3) retry the prompt, (4) secondary truncation. "Provider request-size ceiling errors skip compaction entirely." User text on failure: "Context overflow: prompt too large for the model. Try /reset (or /new)…" plus, if tools had side effects, "Completed tool actions were not replayed; verify their effects before retrying." (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/overflow-context-recovery.ts). After compaction mid-turn the run resumes with `COMPACTION_CONTINUATION_RETRY_INSTRUCTION`: "The previous attempt compacted the conversation context before producing a final user-visible answer. Continue from the compacted transcript and produce the final answer now. Do not restart from scratch, do not repeat completed work, and do not rerun tools unless the transcript clearly lacks required evidence." (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/terminal-resolution.ts).

**Caching.** The prompt is split into a "Stable Prefix" (AGENTS.md etc. at the top), a `stablePromptPrefixCache` to avoid re-hashing, and a "Volatile Suffix" (date, time, messaging) "appended last to minimize cache invalidation" (https://deepwiki.com/openclaw/openclaw/3.2-system-prompt-and-context). Temporal context sits "below the cache boundary, so timezone changes don't invalidate the prefix" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md). A pluggable **context engine** (`ingest`/`assemble`/`compact`, optional `bootstrap`/`afterTurn`/`prepareSubagentSpawn`) can replace the built-in `legacy` engine; `assemble` receives a `tokenBudget` and returns messages plus estimated tokens (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/context-engine.md). Inspection: `/status`, `/context list|detail|map` show per-file, per-tool, per-skill token estimates (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/context.md).

## 4. Tools

**Definition.** Tools are typed-schema objects; the runtime "handles provider-specific constraints like `const` or `enum` mapping and strips unsupported keywords"; "name, description, and parameters" are the indexing vectors for tool search; results are `AgentToolResult` (https://deepwiki.com/openclaw/openclaw/3.4-tools-system). Registration flow: inventory resolution by policy → `wrapToolWithBeforeToolCallHook` → schema normalization per provider → execution routing, all assembled by `createOpenClawCodingTools` (same URL). Plugins register tools through `register(api)` and declare `configSchema` in `openclaw.plugin.json` (https://deepwiki.com/openclaw/openclaw/5.1-plugin-architecture). Tools may declare an `outputSchema`; unknown outputs are shown as `-> ?` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/code-mode.md).

**Description style in the prompt.** The system prompt's Tooling section is "structured-tool guidance"; with `progress_card` enabled it describes "maintaining one durable plan with at most one step marked `in_progress`"; an "Execution Bias" section says "act on actionable requests, continue until done, recover from weak results, verify before finalizing" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md).

**Validation.** Gateway frames are validated with TypeBox `Compile` against schemas that are "the single source of truth" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/typebox.md); `tool_call` returns "a `{ tool, result }` envelope with structured validation" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/tool-search.md). No documented prose for the error returned to the model on invalid arguments.

**Tool count and groups.** Nine categories: Runtime (`exec`, `process`, `terminal`, `code_execution`), Files (`read`, `write`, `edit`, `apply_patch`), Human input (`ask_user`, `secrets`), Web (`web_search`, `x_search`, `web_fetch`), Browser, Operator UI (`screen`), Messaging (`message`), Sessions/agents (`sessions_*`, `agents_wait`, `subagents`, `agents_list`, `session_status`, `get_goal`, `create_goal`, `update_goal`), Automation (`cron`, `heartbeat_respond`), plus media (`view_image`, `image_generate`, `music_generate`, `video_generate`, `tts`) (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/index.md). Groups `group:fs|runtime|web|sessions|memory|messaging|media|ui|automation|nodes|agents|plugins|openclaw`; profiles `minimal` (`session_status` only), `coding` (default), `messaging`, `full`; "Deny policies override allow policies"; hierarchy "base profile → provider profile → allow/deny" with `tools.byProvider` and `tools.toolsBySender` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/config-tools.md). `filterLocalModelLeanTools` "reduces the tool surface for models with smaller context windows" (https://deepwiki.com/openclaw/openclaw/3.4.1-tool-policies-and-filtering); its deny list is `browser, automations, image_generate, message, music_generate, pdf, tts, video_generate`, and lean mode defaults tool search to `{ enabled: true, mode: 'tools', searchDefaultLimit: 5, maxSearchLimit: 10 }` (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/local-model-lean.ts).

**Deferred loading.** Tool Search "gives agents one compact way to discover and call large tool catalogs": `search(query, {limit})` (default 8, max 20, batch up to 16 queries / 50 candidates), `describe(id)`, `call(id, args)`; ranking is "lexical (Okapi BM25 over tool names, descriptions, and first-party parameter names)"; the capability directory is "max 18,000 characters, cache-stable"; "Direct tool exposure is still the right default for small catalogs" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/tool-search.md). Code Mode goes further: the model sees only `exec` and `wait` and "writes a small JavaScript or TypeScript program that searches, describes, and calls the hidden tool catalog" inside a QuickJS-WASI worker (`timeoutMs` 10000, `maxOutputBytes` 65,536, `maxPendingToolCalls` 16, 64 concurrent suspended runs, "model code is hostile"); it only auto-engages for models flagged `"preferred"`, and "Ollama and local models remain unflagged" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/code-mode.md).

## 5. Subagents

**Spawn and isolation.** `sessions_spawn` creates a child in session key `agent:<agentId>:subagent:<uuid>` on a dedicated `subagent` queue lane. Params: `task` (required), `taskName` (`[a-z][a-z0-9_-]{0,63}`), `agentId`, `context: "isolated" | "fork"` (isolated default; fork "branches requester's transcript"), `visible`, `thread`, `model`, `thinking`, `runTimeoutSeconds`, `cleanup: "delete"|"keep"`, `expectsCompletionMessage` (default true), `sandbox: "inherit"|"require"` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md). Sub-agents get `promptMode: "minimal"`, which "omits memory, model aliases, user identity, output directives, messaging, collapsible details, silent replies" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md); they receive "Proactive Orchestration" instructions (https://deepwiki.com/openclaw/openclaw/3.2-system-prompt-and-context).

**Inputs.** The task string, inherited model/thinking (unless `agents.defaults.subagents.model|thinking`), and "the same tool-policy pipeline as parent, then restricted sub-agent layer". At all depths they lose `gateway, agents_list, session_status, cron, message, sessions_send, conversations_*`; leaves also lose `subagents, sessions_list, sessions_history, sessions_spawn` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md).

**Outputs.** The child runs an announce step; the parent "receives internal completion event for review" containing "status, result text, runtime, token usage, estimated cost, session metadata" (same URL). Delivery tries `sendSubagentAnnounceDirectly`, then `runDescendantWake` if the parent is idle, else a `session-delivery-queue`; the result surfaces "as a new model-visible message" (https://deepwiki.com/openclaw/openclaw/3.8-acp-and-sub-agents).

**Limits.** `maxConcurrent` 8, `maxSpawnDepth` 1 (2 enables orchestrators; hard max 5), `maxChildrenPerAgent` 5, `runTimeoutSeconds` 0, `announceTimeoutMs` 120,000, `archiveAfterMinutes` 60 (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md, https://raw.githubusercontent.com/openclaw/openclaw/main/src/config/agent-limits.ts). Admission goes through `reserveChildAdmissionSlot`; backlog through `getSubagentDeliveryBacklogPressure` (https://deepwiki.com/openclaw/openclaw/3.8-acp-and-sub-agents). Agent-to-agent messaging is off by default (`tools.agentToAgent.enabled: false`) (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/multi-agent.md).

## 6. Memory and instructions

**Files and injection order.** Workspace bootstrap files are injected by `CONTEXT_FILE_ORDER`: AGENTS.md (10, "Standing orders and repo-level rules"), SOUL.md (20), IDENTITY.md (30), USER.md (40), TOOLS.md (50), BOOTSTRAP.md (60, first run only), MEMORY.md (70) (https://deepwiki.com/openclaw/openclaw/3.2-system-prompt-and-context). Daily notes live in `memory/YYYY-MM-DD.md`; "Today's and yesterday's dated notes auto-load on `/new` or `/reset`"; a "Dreaming" cron promotes notes into MEMORY.md (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md).

**Budgets.** `agents.defaults.bootstrapMaxChars` 20,000 per file, `bootstrapTotalMaxChars` 60,000 total; USER.md has "a separate 4,000-character budget"; on truncation "the system prompt includes a concise notice without per-file details"; MEMORY.md "remains intact on disk but gets truncated in context" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-workspace.md, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md). Skills inject as an `<available_skills>` XML block — "approximately 97 characters plus name, description, and location lengths" per skill, "~24 tokens per skill"; over `skills.limits.maxSkillsPromptChars` it "preserves identities in compact format, then allocates remaining budget to shortened descriptions"; the model loads a SKILL.md with `read` on demand (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/skills.md).

**Retrieval.** `memory_search` is hybrid "vector similarity … combined with keyword matching" over SQLite FTS5 + vector tables; `memory_get` fetches a file or line range; chunks carry `<!-- importance: [0-9] -->` and provenance `owner|agent|untrusted|system`; file watching debounces reindex at 1.5 s (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md, https://deepwiki.com/openclaw/openclaw/3.4.3-memory-and-search).

## 7. Permissions and approvals

**Trust model.** One trusted operator per Gateway; `openclaw.json` and authenticated callers are trusted; "Session keys route messages but do not confer authorization"; channel messages are untrusted; plugins "run inside the Gateway process with full operator privileges"; "Tools run on the host by default unless Docker/Seccomp sandboxing is explicitly configured" (https://deepwiki.com/openclaw/openclaw/7.1-security-model-and-trust-boundaries). Owner-only "Ring Zero" tools (`gateway`, `bash`) are gated by `GATEWAY_OWNER_ONLY_CORE_TOOLS` (https://deepwiki.com/openclaw/openclaw/3.4.1-tool-policies-and-filtering).

**Exec approvals.** `security`: `deny` | `allowlist` ("Run only allowlisted commands without asking") | `full`; `ask`: `off` | `on-miss` | `always`; `askFallback` default `deny` when no UI answers or the prompt times out; `autoAllowSkills` false. Allowlist patterns are resolved binary paths, bare names, or globs, optionally with an ECMAScript `argPattern` over parsed args (excluding `argv[0]`). Flow: Gateway broadcasts `exec.approval.requested`, a UI answers `exec.approval.resolve`, durable decisions persist in `openclaw.sqlite#exec_approvals_config` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/exec-approvals.md).

**Hook-driven approvals.** `before_tool_call` may return `{ params?, block?, blockReason?, requireApproval?: { title, description, severity?: "info"|"warning"|"critical", timeoutMs?, allowedDecisions?: ["allow-once","allow-always","deny"], onResolution? } }` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/hooks.md).

**Channel access.** `dmPolicy`: `pairing` (default — "Unknown senders receive a one-time pairing code"), `allowlist`, `open`, `disabled`; `groupPolicy` `allowlist` default with mention gating (https://deepwiki.com/openclaw/openclaw/4.3-policy-and-access-control, https://github.com/openclaw/openclaw).

## 8. Hooks / extensibility

**Plugin hooks** (`api.on("hook_name", handler, opts)`), each with a contract: Modify (sequential merge), Claim (first `{ handled: true }` wins), Gate (block stops the chain), Observe (concurrent, ignored returns), Sync modify/gate, Evaluate. Agent turn: `before_model_resolve`, `agent_turn_prepare`, `before_prompt_build`, `before_agent_run` (Gate), `before_agent_reply` (Claim), `before_agent_finalize` (Modify — can "request additional model pass"), `agent_end`. Observation: `model_call_started/ended`, `llm_input`, `llm_output`. Tools: `before_tool_call` (Modify/Gate), `after_tool_call`, `resolve_exec_env`, `tool_result_persist` (Sync Modify), `before_message_write`. Messages: `inbound_claim`, `message_received`, `message_sending`, `reply_payload_sending`, `message_sent`, `before_dispatch`, `reply_dispatch`. Session: `session_start/end` (reasons `new|reset|idle|daily|compaction|deleted|shutdown|restart|unknown`), `before_compaction`, `after_compaction`, `before_reset`. Subagents: `subagent_spawned/ended/progress/delivery_target`. Default per-handler timeouts: 15 s for gates/modifiers, 30 s for `agent_end`/compaction, 2 s pairing, 5 s `gateway_stop`, 120 s `skill_proposal_evaluate`. Options: `matcher` (tool IDs), `priority`, `registrationId`, `timeoutMs` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/hooks.md).

**Internal hooks** are directory-based (`HOOK.md` frontmatter + `handler.ts`) over event families `command|session|agent|gateway|message` (e.g. `command:new`, `session:compact:before`, `agent:bootstrap`); "Returned values do not block or modify operations"; no priority, timeout, retry, or exactly-once. Bundled: `session-memory` saves excerpts on `/new` to `memory/YYYY-MM-DD-HHMM.md`; `compaction-notifier`; `bootstrap-extra-files` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/automation/hooks.md).

**Other seams:** skills (SKILL.md with `requires.bins/env/config`, four-tier precedence) (https://deepwiki.com/openclaw/openclaw/5.2-skills-system); plugins via `openclaw.plugin.json` + `register(api)` with `registerProvider/registerTool/registerChannel/registerContextEngine` (https://deepwiki.com/openclaw/openclaw/5.1-plugin-architecture, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/context-engine.md).

## 9. Error handling and recovery

**Retries within a model.** "Transient network failures before any assistant content can retry up to twice without rerunning tools. The default retry budget is 3 attempts with a fixed 90-second window"; `retry.provider.maxRetries` 3; SDK retry cap 60 s (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/model-failover.md).

**Incomplete-turn recovery.** `DEFAULT_EMPTY_RESPONSE_RETRY_LIMIT = 1` with instruction "The previous attempt did not produce a user-visible answer. Continue from the current state and produce the visible answer now. Do not restart from scratch."; `DEFAULT_REASONING_ONLY_RETRY_LIMIT = 2` with "…recorded reasoning but did not produce a user-visible answer. Continue from that partial turn…"; settled-tools continuation: "…completed its tool calls but did not produce a user-visible answer… Do not repeat completed tool calls or restart from scratch." Retries only when the turn is "replay-safe" (no side effects, no active work, no abort/timeout) (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/incomplete-turn-recovery.ts). `MAX_MISSING_ASSISTANT_RETRIES = 1` (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/terminal-resolution.ts).

**Failover / escalation.** Two stages: auth-profile rotation within a provider, then model fallback through `agents.defaults.model.fallbacks`. Failover-worthy: auth failures, rate limits, overloaded, "timeout-shaped" failures, billing, 404 `model_not_found`, unknown errors with candidates left. **Not** failover-worthy: "Format, context overflow, and explicit aborts". Cooldowns 30 s → 1 m → 5 m (capped); fallback is "for current turn only (doesn't persist selection)" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/model-failover.md). `LiveSessionModelSwitchError` lets a live session "migrate to fallback providers mid-execution" (https://deepwiki.com/openclaw/openclaw/3-agent-runtime).

**Malformed tool input.** Not documented as a distinct path beyond schema validation and the `{ tool, result }` envelope (§4). Tool failures are carried into compaction summaries (`## Tool Failures`, 8 × 240 chars) (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts).

**Context overflow.** See §3: truncate → compact (bounded) → retry → truncate again; request-size-ceiling errors skip compaction (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/overflow-context-recovery.ts).

**Small-model preflight.** Context checks use "an 8k minimum floor and warnings below 20%, plus a hard block below 10% with a 4k floor" of the detected window; `compat.supportsTools: false` disables tool calling entirely as a last resort (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/local-models.md).

## 10. Evals / testing

Vitest is split into lanes (`vitest.unit`, `unit-fast`, `boundary`, `agents-tools` — "agent execution pipelines and tool invocation", `channels`, `tooling`); "changed lane routing" sends "critical agent dispatch logic" edits through "both unit tests and E2E inference regressions"; E2E runs in Docker ("Upgrade Survivor", `mock-openai-server`) and Parallels VMs (https://deepwiki.com/openclaw/openclaw/8.4-testing-strategy). The **QA Lab** runs scenario packs under `qa/scenarios/{agents,channels,runtime}/` (e.g. `subagent-completion-direct-fallback.yaml`, `gateway-restart-inflight-run.yaml`), each with a coverage ID `[category].[feature]`, kind `script|vitest|playwright|flow`, and an isolated ephemeral Gateway; it does **runtime parity** — "compares outcomes across runtimes, tracking `expectedCells` vs `observedCells`" — and validates `qa-evidence.json` (https://deepwiki.com/openclaw/openclaw/8.5-qa-lab-and-scenario-packs). No model-graded evals or benchmark scores are documented.

## 11. What Goliath should borrow

Each item is concrete and has a test.

1. **Add two slots to the scribe brief: `Pending` (user asks not yet answered) and `Ids` (exact identifiers).** OpenClaw's safeguard requires `## Pending user asks` and `## Exact identifiers` and audits that identifiers "extracted from last 10 messages" survive (https://deepwiki.com/openclaw/openclaw/3.6-context-compaction, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts). Goal/Done/Decisions/Next covers progress but not the two things a 3B model drops first. _Test:_ seed a step log with an event ID and an unanswered question; after re-brief, both strings appear verbatim in the guided-JSON brief.

2. **Run a deterministic brief audit with one corrective retry.** `auditSummaryQuality` + `DEFAULT_QUALITY_GUARD_MAX_RETRIES = 1` (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts). Goliath's schema guarantees structure, so the audit is pure regex over the step log: every identifier token (IDs, dates, emails, amounts) in the last N results must appear in `Ids`; the latest user message's noun phrase must appear in `Goal` or `Pending`. On failure, re-run the scribe once with the failure list prepended; on second failure keep the old brief. _Test:_ unit test the audit with fixtures; integration test that a failing first brief triggers exactly one retry.

3. **Re-distill, never carry forward.** Pass the previous brief with the prefix "Previous compaction summary to re-distill… Prune stale, duplicate, or superseded details instead of preserving it verbatim" and the UPDATE rule "move completed items from In Progress to Done" (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts). _Test:_ an item present in `Next` before a step that completes it must move to `Done` and not remain in `Next`.

4. **One bounded "continue" retry before cloud escalation on an empty answer.** OpenClaw retries once with "The previous attempt did not produce a user-visible answer. Continue from the current state and produce the visible answer now. Do not restart from scratch." and only when replay-safe (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/incomplete-turn-recovery.ts). Goliath currently escalates immediately. Borrow `limit = 1`, and the replay-safe guard: retry only if the failing step ran no write tool. _Test:_ mock an empty response then a good one; assert one retry, no escalation, no tool re-execution.

5. **Overflow recovery order: shrink results → re-brief → retry → escalate.** (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/overflow-context-recovery.ts). On a window error Goliath should first re-compress the largest result lines, then force a scribe pass, then retry the conductor once, and only then escalate with the step log. Also borrow "request-size ceiling errors skip compaction" — a single tool result larger than the window goes straight to truncation. _Test:_ inject an oversized result; assert the sequence and that escalation is the fourth event, not the first.

6. **Keep an error tail when compressing tool results.** The truncator matches `error|exception|failed|fatal|traceback` and reserves ~30% of the budget for the tail with a middle-omission marker (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/tool-result-truncation.ts). Goliath's `key: value` compressor should always emit `error:` lines and, when a result is cut, a single `note: middle omitted` line. _Test:_ a 200-line result whose last line is an error compresses to ≤ N lines and still contains the error text.

7. **Cap a single tool result at 30% of the window and all live results at 50%.** `MAX_TOOL_RESULT_CONTEXT_SHARE = 0.3`, `AGGREGATE_TOOL_RESULT_CONTEXT_SHARE = 0.5` (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/tool-result-limits.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/tool-result-truncation.ts). For 4,096 tokens: ~1,200 tokens per result, ~2,048 across the step log, leaving ~2,000 for instructions, brief, and output. _Test:_ a token-estimate assertion on the assembled conductor prompt for a 5-step log.

8. **Hard-clear old results into a placeholder once the scribe has absorbed them; protect the last 3.** Pruning replaces old tool results with `[Old tool result content cleared]` at ~50% usage and never touches "the last three assistant turns" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/session-pruning.md). Goliath: after the scribe runs, steps older than the last 3 keep only `tool`, `args` digest, and `ok/err`; results become a one-line placeholder. _Test:_ after step 6 the conductor prompt contains full results for steps 4–6 only.

9. **Keep call+result pairs atomic in every compaction and log cut.** "Tool results are not valid cut points" and "tool call/result pairs stay together" (https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/compaction.md). _Test:_ property test that any trimmed step log has no orphan call or orphan result.

10. **Fence stale worker results with a run generation.** `activeWriterRunId` / `expectedWriterRunId` and `lifecycleGeneration` ensure "superseded runs cannot commit stale transcript data" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md, https://deepwiki.com/openclaw/openclaw/3-agent-runtime). Goliath has one request in flight but a user interrupt can land while a tool is executing; stamp every step with `runGeneration` and drop results whose generation is stale. _Test:_ interrupt during a slow mocked tool; assert its result never enters the step log.

11. **Queue semantics at step boundaries: `collect` with 500 ms debounce, cap 20, `drop: summarize`; `interrupt` = abort + newest.** (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/queue.md). Goliath cannot steer mid-request, but it can inject queued user text into the conductor prompt at the next step boundary — that _is_ OpenClaw's steer ("visible before the next tool or model decision"). _Test:_ two messages 100 ms apart during a step produce one injected block at the next boundary.

12. **Model-error retry policy: up to 2 same-model retries only if no tool has run in the step; cloud fallback is per-turn, not sticky.** (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/model-failover.md). Also copy the classification: overflow and format errors are _not_ fallback-worthy on their own (they go through item 5 first). _Test:_ an on-device error after a write tool escalates without retry; the next turn tries on-device again.

13. **Approval decision shape and durable allow-always.** Borrow `allowedDecisions: ["allow-once", "allow-always", "deny"]`, `severity: info|warning|critical`, `askFallback: deny`, and allowlist entries with an `argPattern` regex (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/hooks.md, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/exec-approvals.md). Goliath "writes confirm first" becomes: `ask: on-miss` against a persisted allowlist of `(tool, argPattern)`; timeout or no UI → deny. _Test:_ an `allow-always` on `calendar.create` with `argPattern: ^.*family.*$` skips the prompt next time and only for matching args.

14. **Hook contracts: Modify / Gate / Observe with `matcher` and a timeout.** `before_tool_call` (Modify/Gate, 15 s), `after_tool_call` (Observe), `tool_result_persist` (Sync Modify), `before_compaction`/`after_compaction` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/hooks.md). Goliath should expose `beforeToolCall` (may rewrite args, block, or require approval), `afterToolCall`, `beforeBrief`, `afterBrief`, `onEscalate`, each with a per-handler timeout. _Test:_ a `beforeToolCall` that returns `{ block: true, blockReason }` produces a step whose result is the reason and no tool execution.

15. **Progressive disclosure of the tool catalog: one line per tool, ~100 chars, identity first then description.** The `<available_skills>` block costs "~97 characters plus name, description, and location" per entry, and over budget it "preserves identities… then allocates remaining budget to shortened descriptions" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/skills.md). Goliath's conductor should see `name — one-line description` only; the full schema goes to the worker. _Test:_ the conductor prompt's tool block is ≤ 25 tokens × tool count.

16. **When the catalog is large, shortlist with BM25 computed by Goliath, not the model.** Tool Search ranks with "Okapi BM25 over tool names, descriptions, and first-party parameter names", and lean mode for local models uses `searchDefaultLimit: 5, maxSearchLimit: 10` (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/tool-search.md, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/local-model-lean.ts). Goliath: above ~8 tools, rank against the user message + brief and show the conductor the top 5 plus any tool named in `Next`. _Test:_ with 20 tools, "what's on my calendar tomorrow" surfaces `calendar.list` in the top 5.

17. **Ship a static lean deny-list for the on-device tier.** `browser, automations, image_generate, message, music_generate, pdf, tts, video_generate` are dropped for local models (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/local-model-lean.ts). Goliath's equivalent: tools whose results cannot be compressed under item 7 are cloud-only. _Test:_ a tool flagged `tier: cloud` never appears in the on-device conductor's catalog.

18. **Worker → conductor return envelope.** Sub-agent completion carries "status, result text, runtime, token usage, estimated cost, session metadata" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md). Goliath's step record should be `{ status, tool, args, resultLines, ms, tokensIn, tokensOut, generation }` so the escalation payload and the UI both read from one shape. _Test:_ schema test on the step log.

19. **Explicit minimal-mode omission list for workers.** Sub-agents' `minimal` prompt "omits memory, model aliases, user identity, output directives, messaging" (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md). Write down what a Goliath worker prompt _never_ contains (brief, history, other tools, persona) and test it. _Test:_ a worker prompt snapshot contains only the task line, the one tool schema, and the output contract.

20. **Stable-prefix / volatile-suffix prompt layout.** OpenClaw places large stable content first and date/time last "to minimize cache invalidation" (https://deepwiki.com/openclaw/openclaw/3.2-system-prompt-and-context). Even if Apple's session does no prefix caching, ordering (instructions → tool catalog → brief → step log → user text → clock) makes prompt-size regressions diffable. _Test:_ golden-file snapshot of the conductor prompt with the clock line last.

21. **Once-per-cycle scribe guard and a failure cap.** Memory flush runs once per compaction cycle and gives up after `MAX_FLUSH_FAILURES = 3` (https://raw.githubusercontent.com/openclaw/openclaw/main/src/auto-reply/reply/agent-runner-memory.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/extensions/memory-core/src/flush-plan.ts). _Test:_ three consecutive scribe failures mark the brief `stale: true` and escalate rather than loop.

22. **"One durable plan with at most one step marked `in_progress`."** (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md). This is Goliath's flat-plan invariant, stated as a schema constraint. _Test:_ reject any conductor output with more than one `in_progress`.

23. **UI progress lines: ≤ 8 lines, ≤ 120 chars each, word-aware, tool-status phrasing.** (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/streaming.md). Cheap, matches Helen's "Helen is checking your calendar" copy rules. _Test:_ snapshot of the progress card for a 10-step run.

24. **Scenario packs with coverage IDs and runtime parity.** `qa/scenarios/<area>/<name>.yaml`, coverage `[category].[feature]`, `expectedCells` vs `observedCells` across runtimes (https://deepwiki.com/openclaw/openclaw/8.5-qa-lab-and-scenario-packs). Goliath's eval harness: YAML scenarios run against on-device and cloud-fallback and diff the outcome cells. _Test:_ the suite fails if a scenario passes on cloud but not on device without an `escalate` cell.

25. **Small-window preflight.** Warn below 20% remaining and hard-block below 10% (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/gateway/local-models.md). Goliath: refuse to dispatch a conductor call whose estimated prompt exceeds 90% of 4,096; run the scribe instead. _Test:_ deterministic token-estimate threshold test.

## 12. What does not transfer to a 4k on-device model, and why

1. **Every absolute budget.** `reserveTokens: 16384`, `keepRecentTokens: 20000`, 16k-char summaries, 16,000/32,000/64,000-char tool results, 20,000/60,000-char bootstrap files, 18,000-char tool directory (https://raw.githubusercontent.com/openclaw/openclaw/main/packages/agent-core/src/harness/compaction/compaction.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/tool-result-limits.ts, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/tool-search.md). Each one alone exceeds Goliath's whole window. Only the _ratios_ (0.3 / 0.5 / 3-turn protection) survive.

2. **The fifteen-section system prompt and persona files.** Tooling, Execution Bias, Promised Work, Safety, Skills, OpenClaw Control, Workspace, Documentation, Sandbox, Temporal, Output Directives, UI Presentation, Collapsible Details, Runtime, Reasoning, plus AGENTS/SOUL/IDENTITY/USER/TOOLS/MEMORY files (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/system-prompt.md). Goliath gets one short instruction block per role; persona lives in the app, not the prompt.

3. **Free-text summaries with heading audits.** OpenClaw needs `auditSummaryQuality` and corrective retries because the summary is Markdown (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/agent-hooks/compaction-safeguard.ts). Goliath's guided JSON makes the _structural_ audit free; only the content audit (item 11.2) carries over.

4. **Code Mode.** The model writing JavaScript against a hidden catalog in QuickJS (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/code-mode.md) is explicitly gated to "preferred" frontier models and "Ollama and local models remain unflagged"; a 3B model with guided JSON and no logprobs should not be asked to author programs, and one flat step per call is the whole point of the conductor.

5. **Model-issued tool search.** `tool_search` → `tool_describe` → `tool_call` costs three round trips (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/tool-search.md); with one request in flight and ~1–2 s per call on device that is latency Goliath cannot spend. Goliath does the ranking itself (item 11.16).

6. **Mid-run steering.** `steer` injects "before the next tool or model decision" into a live runtime (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/queue.md). Goliath has no live runtime between requests; the equivalent is injection at the conductor boundary only.

7. **Parallel subagents.** `maxConcurrent: 8`, `maxChildrenPerAgent: 5`, nested depth up to 5, announce queues and backlog pressure (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/tools/subagents.md, https://deepwiki.com/openclaw/openclaw/3.8-acp-and-sub-agents). One request in flight means Goliath's workers are strictly sequential; there is nothing to admit, queue, or wake.

8. **Provider failover and auth rotation.** Cooldown ladders, profile rotation, `LiveSessionModelSwitchError`, 48-hour run timeouts (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/model-failover.md, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/agent-loop.md). Goliath has exactly one local provider and one cloud fallback; a two-entry chain with per-turn fallback (item 11.12) is the entire policy.

9. **Reasoning-only retry.** `DEFAULT_REASONING_ONLY_RETRY_LIMIT = 2` handles models that emit thinking without an answer (https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/embedded-agent-runner/run/incomplete-turn-recovery.ts). Guided-JSON output has no reasoning channel, so only the empty-answer branch applies.

10. **Overflow string tables.** "Dozens of provider-specific overflow strings" (https://deepwiki.com/openclaw/openclaw/3.6-context-compaction). Goliath reads one typed error from the on-device framework via the AI SDK provider; the recovery _order_ transfers, the detection table does not.

11. **Hybrid vector memory in context.** `memory_search` over SQLite FTS5 + embeddings with OpenAI as default provider, chunks with importance and provenance (https://raw.githubusercontent.com/openclaw/openclaw/main/docs/concepts/memory.md, https://deepwiki.com/openclaw/openclaw/3.4.3-memory-and-search). Search results are themselves tool results that must fit item 11.7; on device the durable store is Convex and the brief is the only memory the model sees.

12. **In-process hooks with 15–120 s budgets and full host access.** Plugins and hooks "run inside the Gateway process with full operator privileges" (https://deepwiki.com/openclaw/openclaw/7.1-security-model-and-trust-boundaries, https://raw.githubusercontent.com/openclaw/openclaw/main/docs/plugins/hooks.md). Goliath hooks run inside a React Native app; keep the contracts (item 11.14) but budgets must be sub-second and hooks cannot shell out.

13. **Exec/sandbox machinery.** Host exec, Docker sandboxes, Crabbox, node dispatch, stderr tails (https://deepwiki.com/openclaw/openclaw/7.3-sandboxing-and-isolation, https://raw.githubusercontent.com/openclaw/openclaw/main/src/agents/sessions/tools/limits.ts). Goliath's tools are typed app capabilities, not shells; only the approval decision shape survives.

14. **Prompt-cache assumptions.** Stable-prefix layout is justified by provider-side caching (https://deepwiki.com/openclaw/openclaw/3.2-system-prompt-and-context). Whether Apple's on-device session reuses a prefix is not established here; adopt the ordering for determinism (item 11.20), not for a cache win.
