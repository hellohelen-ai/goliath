# DeepSeek Harness (`dsh`) — research brief for Goliath

Researched 2026-09-02 from the DeepWiki (indexed at commit `cd5ef8`, 28 Aug 2026), the GitHub README, the repo's `docs/` tree, package READMEs, and a handful of source files. Repo files were fetched from `raw.githubusercontent.com/deepseek-ai/deepseek-harness/master/<path>`; they are cited below by their `github.com/.../blob/master/<path>` URL, which is the same file.

Goliath context for the reader: ~3B on-device model, 4,096-token window, one request in flight, guided JSON output, no logprobs. Conductor plans one flat JSON step; each worker gets a fresh context and one tool and returns only arguments; Goliath executes the tool; results compressed to `key: value` lines; writes confirm first; repeated call / empty answer / malformed plan (after one retry) / model error escalates to a cloud fallback with the step log; a scribe keeps a 60-word rolling brief with fixed slots (Goal/Done/Decisions/Next).

---

## 1. What it is, in 5 lines

1. `dsh` is DeepSeek's open-source, MIT-licensed agent harness — "an open-source agent harness developed by DeepSeek AI" built on an "everything-is-a-plugin architecture" powered by a vendored Cordis plugin framework; it runs as a CLI and a local Web UI (`npx @deepseek-ai/dsh web` on `127.0.0.1:3080`) and is in "developer preview" with "COMPATIBILITY-BREAKING CHANGES" promised. https://github.com/deepseek-ai/deepseek-harness
2. Every component — LLM adapter, tool registry, session log, the agent loop itself — is a plugin exposing a service on a shared typed `ctx`; capabilities are "seams" (Service Definition → Provider → Consumer, e.g. `ctx.llm` with `llm-deepseek` / `llm-pi-ai`, `ctx.fs` with `fs-local`). https://deepwiki.com/deepseek-ai/deepseek-harness
3. The model's context is _derived_, never stored: an append-only `SessionEvent` log is "the single source of truth" and `deriveMessages()` projects the LLM history from it; compaction is a positional `replace` over that projection. https://deepwiki.com/deepseek-ai/deepseek-harness/3.3-session-log-and-persistence
4. It ships 57 model-facing tools across 24 packages (bash, read/write/edit, glob/grep, web, subagent, todo, skill, goals, ralph, workflow, jobs, MCP, …) and a full agent-collaboration plane (approval, permission presets, ask-user, hooks, skills). https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md
5. Monorepo: `apps/` (CLI), `packages/core/` (session, agent, tools — "the product API spine"), `packages/llm/`, `vendor/` (Cordis); Node 22.19+/24+, pnpm, Vitest with 100 % per-file coverage as a gate. https://deepwiki.com/deepseek-ai/deepseek-harness · https://deepwiki.com/deepseek-ai/deepseek-harness/8-testing-and-quality-infrastructure

## 2. The main loop

**Vocabulary.** A **step** is "one model request plus the tools it calls"; a **turn** is "zero or more steps: it opens before its first input is claimed and closes once nothing is owed." https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md · Glossary: a turn "start[s] when input messages are claimed and end[s] when the agent has no more output or pending work." https://deepwiki.com/deepseek-ai/deepseek-harness/10-glossary

**Turn flow (ordered).** `turn/start` → claim next-step input and queued message from the inbox → assemble prompt sections + tool schemas → `agent/pre-step` (listeners "may rewrite or reject the step input batch") → `step/start` (log user messages) → derive model history from the session log → `agent/request` → `llm/stream` → tool execution `tools/pre-execute` → `tools/execute` → `tools/post-execute` → `step/end` → loop or close: `agent/turn-stopping` → `turn/end`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.1-agent-loop-and-lifecycle

`ReactLoopAgent` is the default `Agent`; the five-phase cycle is Claim → Assemble (`assembleContextFor`) → Request (`ctx.llm`) → Execute (`ctx.tools`) → Repeat "if tools require another request." https://deepwiki.com/deepseek-ai/deepseek-harness/3-agent-system

**Inbox.** Agents own two ordered pending lists — `next-turn` (queued follow-ups) and `next-step` (steering and injected context processed immediately) — reached via `send(message, target, wakeup)` or the aliases `followup()`, `steer()`, `inject()`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md

**Tool execution and result return.** Each call is logged as `tool/call` _before_ execution, runs through the guarded pipeline, and its single model-facing outcome is logged as `tool/result`; "Active-batch additionalContexts [are] added FIFO after tool results recorded." Tool batches use "a bounded rolling pool pattern," with "reclassification occurring before each execution cycle." https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-execution-pipeline.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/agent-lifecycle.md

**Parallelism.** `DEFAULT_MAX_PARALLEL_TOOL_CALLS = 10` (`maxParallelToolCalls`; `1` forces serial). Parallel execution is only allowed when `ToolDefinition.isConcurrencySafe(args)` returns `true`; exclusive tools "do not overlap with other tool executions to prevent race conditions (e.g., multiple tools editing the same file)." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.2-tool-registry-and-execution-pipeline

**Step limits.** There are none in the loop: "No built-in turn budget exists… a policy that bounds runaway turns must cancel from an existing lifecycle extension point such as `agent/turn-stopping`." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md

**Stop conditions.** A turn ends on "natural stop and next-step inbox empty"; `agent/turn-stopping` is a serial event "fire[d] before turn closure when no tool calls remain" and a `Stop` hook there "can force continuation." https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/agent-lifecycle.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md · https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills

**Streaming and interrupts.** Tokens "stream back via `llm/stream`" as normalized `StreamChunk`s (`block-start`/`block-end`, `text-delta`, `reasoning-delta`, `usage`, `finish` with `stop | length | content-filter | error`); a `BlockAssembler` "handles the state machine for nested blocks and tool call parsing." `cancel(cause, options)` "clears the inbox and aborts the running `AbortController`," `keepInbox: true` preserves queued messages; `steer()` routes to `next-step` with automatic wakeup. Cancel causes are typed: user, parent, hook, disposed. https://deepwiki.com/deepseek-ai/deepseek-harness/3.5-llm-adapters-and-streaming · https://deepwiki.com/deepseek-ai/deepseek-harness/3.1-agent-loop-and-lifecycle · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md

**Agent status** is just `idle` or `running`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/agent-lifecycle.md

## 3. Context management

**Principle.** "Model-visible means logged": anything reaching a model request must be reconstructible from the log through `deriveMessages()`; only the final `assistant/message` is projected (intermediate `assistant/chunk`s are filtered). https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.3-session-log-and-persistence

**Triggers (`compaction-basic`, the sole backend).**

- _Pressure_: on `agent/pre-step`, before request derivation. Pressure = `measurement.totalTokens` from `meter.measure(agent.session)` vs `spec.thresholdTokens`; compaction runs when `totalTokens < thresholdTokens` is false. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/index.ts
- _Context-overflow_: on `agent/request-error` only for `CONTEXT_WINDOW_EXCEEDED`; it "bypass[es] normal threshold and retention policies," attempts "maximal balanced head reduction," and returns `{ kind: 'retry' }` only after the surface replacement advances. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/agent-lifecycle.md
- _Manual_: `/compact` → `compactNow()`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md

**Thresholds (defaults).** `thresholdRatio: 0.8` — "Start condensing at `floor(routedContextWindow × ratio)`"; `retainRatio: 0.16` — "Recent conversation kept verbatim as a fraction of the routed context window" (or absolute `retainTokens`, mutually exclusive); `maxTokens: 8192` output cap for the summarization request; `compactionRetries: 1` extra attempt when pressure remains; `maxOverflowRetries: 1`; `auto: true`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/config-catalog.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/README.md

**Region selection algorithm (`selectCompactableRange`).** Walk backwards from the tail accumulating per-node tokens (`accumulated += pricedNodes[index]!.tokens`) until `accumulated >= retainTokens`; then `while (keepFromIdx > 0)` step the cutoff earlier until `toolPairingBalancedBefore(session, surfaceNodes[keepFromIdx]!)` holds; return `{ start: first, end: cutoff }` — the oldest balanced span. Region boundaries "preserve tool-call/result pairing but not whole turns." Viability: the summary is rejected if `framedSummaryTokenCount >= prepared.shadowedRouteTokenCount`. If the range is null, nothing changes; after retries, it throws `compaction still above threshold after ${spec.compactionRetries + 1} compaction attempts`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/region.ts · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/index.ts

**Prune-then-summarize order.** `if (prune !== undefined) { prune.pruneSession(agent.session); measurement = meter.measure(agent.session); }` and only then select a range and `compactRegion()` → `summarize()`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/index.ts

**Summarizer input.** The summarizer sees the _same_ system prompt and tool schemas as the live conversation ("for prefix-cache alignment"), the shadowed-region messages replayed verbatim, plus one final user message carrying the fixed instruction; tagged `purpose: 'compaction'`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/summarizer.ts

**Summary content (verbatim instruction).**

> You are now acting as a compaction engine for this AI coding assistant. Condense the conversation ABOVE into a structured checkpoint that lets another model resume the work with no loss of essential context.
>
> Output EXACTLY the Markdown structure below: keep every section, in order. Use terse bullets, not prose paragraphs. Write "(none)" for an empty section — never drop a section.
>
> `## Primary Request and Intent` / `## Key Technical Concepts` / `## Files and Code` / `## Errors and Fixes` / `## Pending Jobs` / `## Current Work` / `## Next Step` (— "the single next action, directly in line with the most recent request, or "(none)"") / `## Critical Context`
>
> Rules: Write concise English engineering prose. Preserve exact file paths, commands, error strings, identifiers, numeric values, function signatures, and syntax fragments. Capture user feedback and explicit instructions faithfully, especially corrections. Do NOT mention this summarization request or that the context was compacted. Output only the checkpoint text: do not call any tool or take any other action. If the conversation already contains a `<compacted-summary>` block, it is a PRIOR checkpoint. Do not copy it forward verbatim: preserve still-true facts, drop stale ones, and merge newer information into a single consolidated summary under the same structure.

The replacement is a `user/message` with `surfaceOp: { op: 'replace', start, end }`, wrapped in `<compacted-summary>…</compacted-summary>` and preceded by the preamble: "This is an automatically generated checkpoint condensing an earlier span of the conversation to free up context. Treat the captured context as established background and build on it without restating it. Continue the task directly from the messages that follow, without acknowledging this checkpoint." Raw events stay in the log; `compaction/start` / `compaction/summary` / `compaction/end` are log-only and act as a lock. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/summarizer.ts · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md

**Tool-result truncation (`compaction-tool-result-pruner`).** "Trims any result with more than 8,192 text characters to its first 4,096 plus its last 1,024" (`thresholdChars: 8192`, `headChars: 4096`, `tailChars: 1024`); the marker is `\n\n[... tool result middle pruned ...]\n\n`; measured in Unicode code points; non-text blocks keep their positions and cost zero; reports `PrunedEntry` (original seq, replacement seq, call ID, char counts) and aggregate `charsRemoved`. The standard preset ships these exact numbers. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-tool-result-pruner/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-presets/presets/standard/agent.cordis.yml

**Large outputs at the tool boundary.**

- `spill-policy`: when a result exceeds `maxInlineBytes` (no default; omitting disables), the full text goes to a spill artifact and the model sees a head/tail preview plus: "(Omitted N bytes. Full formatted result stored at: /…/session-…/…-web_fetch.txt. Use read with offset/limit, or grep this path to search within it.)" — the notice is sized to fit the remaining budget. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/spill/spill-policy/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/spill/README.md
- `output-retention` (`TextRetainer`): `head` / `tail` / `headTail` strategies, byte-based, never reconstructs a codepoint across the omitted middle, returns `{ text, omittedBytes }`; standard clause "Omitted [N] [unit]." followed by tool-specific recovery guidance, e.g. "Results capped at [kept]. Narrow the pattern, path, or include to see more." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/util/output-retention/README.md
- Subprocess output: in-memory tail "(e.g., 64KB)", spill to a `wx`-opened temp file, then discard the head if the spill cap is exceeded while keeping the tail. https://deepwiki.com/deepseek-ai/deepseek-harness/4.2-shell-subprocess-and-terminal
- `read`: `readLimit` 2000 lines (default and max), `readMaxLineLength` 2000 chars ("... (line truncated to <max> chars)"), `readMaxBytes` 51,200, files ≥ 10,485,760 bytes stream. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/fs/tool-fs/README.md
- `web_fetch`: `fetchMaxOutputChars` default 200,000; `web_search`: `searchMaxQueries` default 4. https://deepwiki.com/deepseek-ai/deepseek-harness/7.3-goals-todos-workflows-and-web-tools

**Caching.** The summarizer deliberately reuses the live system prompt and tool schemas "rather than invalidating [the provider's warm prefix cache] with a separate summarizer system prompt." Skill catalog and instruction re-injection are digest-gated (see §6) to avoid churning the prefix. Sessions persist write-behind in batches to JSONL or SQLite (FTS5); a crash is repaired by synthesizing `turn/end` via `interruptedTurnClosers`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/summarizer.ts · https://deepwiki.com/deepseek-ai/deepseek-harness/3.3-session-log-and-persistence

**Per-step context injections.** `time-context` injects three lines at every eligible pre-step (ISO timestamp with offset + IANA zone; zone policy; elapsed whole seconds since the previous model-visible message / previous time-context event), `refreshIntervalMs: 0`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/time-context/README.md

## 4. Tools

**Definition.** `defineTool({ name, description, parameters, output: { schema, render? }, execute, timeoutMs?, presentCall?, presentResult? })`; `isConcurrencySafe` and optional `finalizeContent` for model-facing normalization. The registry "validates JSON schemas and ensures `output` declarations are present at registration time." Registration is scope-aware: agent-local tools shadow global ones with the same name; `ctx.tools.restrict(filter)` masks globals; `docs/tool-catalog.md` is generated from `ctx.tools.schemas()`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.2-tool-registry-and-execution-pipeline

**Description style.** One imperative sentence stating what the tool does and what it returns; parameters get one-line descriptions with defaults inline. Verbatim examples from the catalog:

- `bash`: "Execute a bash command (`bash -c`) and return its stdout/stderr. Each call runs in a fresh shell: no state persists between calls." — `description` (required): "Clear, concise description of what this command does in active voice, 5-10 words."
- `read`: "Read a UTF-8 text file and return line-numbered content." — `limit`: "Maximum number of lines to return. Defaults to 2000."
- `edit`: "Edit an existing UTF-8 text file by replacing literal text." — `old_string`: "Literal text to replace. Must match exactly."
- `subagent`: "Delegate a self-contained task to a subagent working in its own context, returning results without intermediate steps." — `prompt`: "Complete, self-contained task for the subagent with all necessary context."; `description`: "Short (3-5 word) description of the delegated task."
- `todo_write`: "Record and update a structured task list for current work. Sends the ENTIRE list, replacing the previous one."
- `skill`: "Load the full instructions for an available skill before acting on a matching task."
- `ask_user_question`: "Ask the user a concise question when you need confirmation, choice, or missing information before proceeding."
- `ralph`: "Run a foreground fresh-agent loop toward one immutable objective with new child contexts each round."
  https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md

**Validation.** "Model arguments are validated before execution; invalid input becomes a normal error result" — the body never runs on schema-invalid input. `tool/call` is logged "with unparsed JSON arguments." Stable validation strings, e.g. `file_path must be a non-empty string`, `limit must be less than or equal to <max>`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/persistence-catalog.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/fs/tool-fs/README.md

**Pipeline (14 stages).** `tool/call` logged → `tools/pre-execute` waterfall (hooks, permission, sandbox) → monotonic guards (`ctx.tools.guard()`: "a returned reason denies the call, and no later listener can turn that denial back into permission") → approval gate (`ctx.approval`, "absent responses trigger denial") → `tools/execute` (timeout/retry/metrics around dispatch) → tool body → `fs/write-intent` / `fs/edit-intent` gate → `tools/post-execute` (accept / block / replace / add context) → normalization (throws become `isError`) → `finalizeContent` → `tools/result` (frozen, observe-only) → additional contexts FIFO → `tool/result` logged → batch settlement / `presentResult()`. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-execution-pipeline.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md

**Result formatting.** A canonical JSON value matching the declared `output` schema plus optional rendered content. Bash renders as stdout tail, `[stderr]` section, then independent single-line markers: `[output truncated; full output: <path-or-(unavailable)>]`, `[sandbox: file access denied under <mode> mode]`, `[timed out after <timeoutMs>ms]`, `[killed by signal: <signal>]`, `[exit code: <exitCode>]`; empty output is exactly `(no output)`. Exit code, signal, `timedOut`, `aborted` are reported "independently" because "a process can time out AND exit 0." Read renders `<lineNumber>: <text>` with a pagination footer; write returns "Created file" / "Updated file"; edit returns "The file <displayPath> has been updated successfully." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/shell/tool-bash/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/fs/tool-fs/README.md

**Errors never end the turn.** "Unknown and throwing tools become structured errors (`UNKNOWN_TOOL`), so a call fails without ending the turn"; timeouts return `Error: tool call timed out after <ms>ms` with `{ name: 'ToolTimeoutError', code: 'TOOL_TIMEOUT' }`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/guard/timeout-policy/README.md

**Read-before-write.** A successful `read` emits `fs/observed`; `write`/`edit` request `fs/write-intent`; if the file changed the policy returns a `replaceIfVersion` guard or `FS_NOT_OBSERVED` ("— read the file, then retry") / `FS_STALE_VERSION` ("— re-read the file, then retry"); `FS_AMBIGUOUS_EDIT` when `old_string` matches more than once. Per-file locks; atomic temp-file rename. https://deepwiki.com/deepseek-ai/deepseek-harness/4.1-filesystem-tools-and-observation · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/fs/tool-fs/README.md

**Tool count and presentation.** 57 tools / 24 packages. `tools.mode` is `native` (JSON tool calls), `ptc` (code mode: a reserved `run_code` tool with a generated TypeScript/Python SDK; `maxParallelSubCalls: 10`), or `both`. Tool schemas are part of system-prompt assembly, ordered by `toolOrder` (with one `'<unlisted-tools>'` entry) or lexicographically. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/system-prompt/README.md

**Deferred loading.** No deferred _tool_ loading is documented. The deferred-content pattern is skills: the catalog holds names + descriptions only, and the body is fetched by the `skill` tool on demand (§6). MCP tools register eagerly as `mcp__<server>__<name>` (≤ 64 chars, 12-hex SHA-256 suffix on collision) and resync on `tools/list` changes. https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills

## 5. Subagents

**Providers.** In-process `spawn` (fresh context) and `fork` (inherits the parent's completed turns); out-of-process ACP (JSON-RPC over stdio; teardown `stdin.end()` → `SIGTERM` → `SIGKILL`), Claude Code (`@anthropic-ai/claude-agent-sdk`), Codex (`codex app-server --stdio`), and a full `dsh-sdk` runtime. https://deepwiki.com/deepseek-ai/deepseek-harness/3.4-subagent-orchestration

**Isolation (spawn).** Inherits cwd, session lineage, provider/model, reasoning effort, output-token limit, and an explicitly configured persona. Gets fresh: "Empty conversation history… Isolated KV cache… Task prompt as sole user message… No parent transcript." "The child gets a fresh flat registration scope: parent tool restrictions and authority are never imported, and the filter the tool applies is composition, not a parent-derived grant." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subagent/subagent-spawn-in-process/README.md

**Inputs.** `description` (3–5 words), `prompt` (complete, self-contained), optional `run_in_background`; per-child `persona` (shadows `deployment:persona`) and `toolFilter`; `agentOptions` for model and token limits. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subagent/tool-subagent/README.md

**Outputs.** `SubagentResult { output, stopReason }` with `stopReason ∈ completed | aborted | error | max-tokens | refusal`. Foreground: "Success returns only the child's final text. Failures map non-completed stop reasons to error headlines, append provider diagnostics, and include any partial assistant text." Background: `"started background subagent job <id>"` (one-shot) or `"started subagent <childId>"` (continuable). Continuable children talk via `followup` (parent → child) and `reportFrom` (child → parent, `quiet` injection or `wakeup`). https://deepwiki.com/deepseek-ai/deepseek-harness/3.4-subagent-orchestration · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subagent/tool-subagent/README.md

**Limits.** `maxDepth: 3` (`0` forbids delegation; `'provider-managed'` for external providers); `SubagentDepthError` on breach; no documented concurrency cap. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subagent/tool-subagent/README.md

**Ralph — the fresh-context loop (closest to Goliath).** Each round spawns a child that "receive[s] no parent conversation and no prior child session"; the round prompt is: "You are one fresh worker in a foreground Ralph loop. You receive no parent conversation and no prior child session. Do not call the ralph tool: this round already is its worker." + `"Immutable objective:\n" + objective` + `"Ralph round: " + round + " of " + maxRounds + "."` + `"Previous structured handoff:\n" + prior` where `prior` is `'(none — this is the first round)'` or `JSON.stringify(previous)`. The handoff schema is `{ status: 'continue' | 'complete' | 'blocked', summary: string, evidence: string[], nextSteps: string[], blocker: string }`, `additionalProperties: false`; `maxHandoffChars: 16384`, `maxResultChars: 16384`, `maxRounds: 256` (deployment ceiling; the standard preset sets 64). "Completion and blockers are worker reports, not independent certification." Errors: "Ralph round report exceeds maxHandoffChars", "Ralph workflow returned a malformed round report". https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workflow/tool-ralph/src/index.ts · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workflow/tool-ralph/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-presets/presets/standard/agent.cordis.yml

**Goal rounds (same-session).** `goal-round-driver` re-prompts at whole-agent idle with a `<goal_round>` block: `Objective: ${JSON.stringify(goal.objective)}` / `Round: ${round}/${goal.maxGoalRounds}` then "Continue working toward the objective in this same session. Treat the current workspace, tool results, and durable session state as authoritative; inspect them instead of assuming earlier narration is still current." At the cap it records blocker `round-limit` ("Goal reached its configured limit of ${goal.maxGoalRounds} rounds."). ## 6. Memory and instructions

**System prompt.** Ordered sections `{ name, order, text }` (ascending, ties by name): `-1000` fixed harness identity ("You are an AI agent powered by DeepSeek Harness.", `includeHarnessIdentity: true`), `0` deployment persona (default empty string; the standard preset's is "You are a coding agent powered by the {{model}} model. Your working directory is {{cwd}}."), `50` `plan:policy` when plan mode is active, `100` e.g. `tool:bash`. A preset persona shadows the deployment one by reusing the section name `deployment:persona`; `complete: true` makes it the sole section. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/system-prompt/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/persona/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/plan.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-presets/presets/standard/agent.cordis.yml

**Instruction files (`agent-instructions`).** Candidates `AGENTS.md`, `CLAUDE.md`, local overlays `AGENTS.local.md`, `CLAUDE.local.md`; `$DSH_HOME/AGENTS.md` first, then the project chain (root marker `.git`) broad-to-specific. Injected as ordinary user-role messages: `<system-reminder>\nInstructions from: [filepath]\n[content]\n</system-reminder>`; removals produce "Instructions removed: [path]". Budgets: `maxBytes` (required; standard preset 65,536) "on the complete rendered baseline message," `maxSourceBytes` 1,048,576 per file; enforcement "drops whole broader files before truncating the most-specific file." Change detection by SHA-1: "An unchanged path with an unchanged digest is never injected again"; re-checked after `read`/`write`/`edit` and on resume. "Context is durable: injected instructions and references enter session history" and survive compaction. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/README.md

**Skills.** `<name>/SKILL.md` or `<name>.md`, name `^[a-z0-9]+(?:-[a-z0-9]+)*$`; six ranked roots (`.dsh/skills` 100, `.agents/skills` 200, custom 300, `<dshHome>/skills` 400, `<agentsHome>/skills` 500, bundled 600). **Working memory.** `todo_write` appends a `todo/write` event holding "the entire task list as a snapshot"; statuses `pending | in_progress | completed`; contents non-empty and unique; with `allowParallelInProgress: false` it "rejects any list with more than one `'in_progress'` item"; the projection "resets to `null` on `turn/start` events to force re-planning each turn." https://deepwiki.com/deepseek-ai/deepseek-harness/7.3-goals-todos-workflows-and-web-tools

## 7. Permissions and approvals

**Sandbox modes.** `read-only`, `workspace-write` (workspace root + private temp), `danger-full-access`; fail-closed — if the sandbox backend is missing, `SANDBOX_UNAVAILABLE` is thrown. Linux uses Landlock/bubblewrap via a ~300-line C11 `landlock-run` (`--ro`/`--rw`, launcher failures exit 125 with a `landlock-run:` prefix); Windows uses `WRITE_RESTRICTED` restricted tokens with a workspace SID and a per-session temp SID. https://deepwiki.com/deepseek-ai/deepseek-harness/4.3-sandboxing-and-security

**Approval seam (`ctx.approval`).** `ApprovalRequest { agent, toolName, callId?, reason?, signal? }`; closed outcomes `allowed-once` ("grants only the asked-about action"), `rejected`, `cancelled`, `unavailable`; "Callers deny on `rejected`, `cancelled`, and `unavailable`." Policies: `ask` (default; no answerer → `unavailable` → deny) and `never` (every ask → `rejected`). Audit pair `approval/asked` / `approval/decided` "are log-only and do not enter the model transcript." No timeout is specified. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/approval.md · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/persistence-catalog.md

**Presets.** `workspace-write` = sandbox `workspace-write` + approval `ask`; `danger-full-access` = sandbox `danger-full-access` + approval `never`; `custom` is reserved for a derived mismatched state. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/permission-presets.md

**Escalation from inside a tool call.** When the sandbox denies a command (matched by provider `denialSignatures` in stderr), the model "may retry once in the same turn with `sandbox_permissions` (the narrowest wider mode sufficient) and a one-sentence `justification`"; the user prompt is raised on that retry; a request "without a prior denial, one not strictly wider than the current mode, or a rejected escalation fails closed without execution." https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/shell/tool-bash/README.md · https://deepwiki.com/deepseek-ai/deepseek-harness/4.3-sandboxing-and-security

**Asking the user.** `ask_user_question` takes `questions[{ id, question, header?, options?[{label, description}], multi_select? }]` ("(Recommended)" appended to a label) and returns compact JSON `{ "answers": [{ "id", "selected": [...], "custom"? }] }`; without an answerer the tool errors. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/tool-ask-user/README.md

## 8. Hooks / extensibility

**Event bus.** Three modes — `emit`, `parallel`, `waterfall` (sequential, each listener decides whether to `next()`). Key waterfalls: `agent/pre-step` (15 consumers incl. `agent-instructions`, hooks), `agent/request`, `agent/request-error` (`compaction-basic`, `llm-retry`), `system-prompt/assemble`, `tools/pre-execute`, `tools/execute` (`timeout-policy`, `session-checkpoint-policy`), `tools/post-execute` (`repeat-tool-reminder`, `spill-policy`, hooks), `approval/request`, `fs/write-intent`. https://deepwiki.com/deepseek-ai/deepseek-harness/2.3-event-bus-and-capability-seams · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/event-producer-consumer.md

**Hook bridges (Claude Code / Codex `hooks.json` compatible).** Events `SessionStart`, `UserPromptSubmit` (→ `agent/pre-step`), `PreToolUse` (→ `tools/pre-execute`), `PostToolUse` (→ `tools/post-execute`), `Stop` (→ `agent/turn-stopping`, "can force continuation"). Hooks are shell commands fed snake_case JSON (`session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`, `permission_mode`; plus `tool_name`, `tool_input`, `tool_use_id` / `turn_id`, `prompt` / `stop_hook_active`, `last_assistant_message`). Exit 2 blocks ("the tool is not run and an error message is surfaced" — `blocked by PreToolUse hook` unless a reason is given); other codes are logged only; plain stdout becomes injected context; merge precedence deny > ask > allow; default per-hook timeout 600,000 ms. https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/hooks/hooks-codex/src/index.ts · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/hooks/README.md

**Guards (shipped, on by default in `dsh-base`).**

- `repeat-tool-reminder`: canonical key = tool name + arguments after "deep key-sort plus `JSON.stringify`"; consecutive identical calls counted, a different tracked call resets to 1; `thresholds: [3, 5, 8]`; at 3 it injects a `user/message` after the step's tool results: "You are repeating the exact same tool call with identical arguments. Carefully analyze the previous result before calling again: if the task is not complete, try a different approach or different arguments instead of repeating the call."; at 5 and 8: "Repeated tool call detected: - tool: <toolName> - consecutive_calls: <count> - arguments: <canonicalArguments> The repeated calls are not making progress…" (`argumentsPreviewChars: 500`, `include`/`exclude`). https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/guard/repeat-tool-reminder/README.md
- `timeout-policy`: zero-config; reads each tool's `timeoutMs`; web tools default 30,000 ms, `bash`/`read`/`write`/`edit` declare none; cooperative only ("never hard-stops downstream work"). https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/guard/timeout-policy/README.md

**Composition.** Profiles (`web`, `headless`) stack bundles (`dsh-base`, `dsh-headless`, `dsh-web-app`) of `cordis.yml` rows, patched by `cordis.patch.yml`; config validated by Zod schemas generated from TS interfaces; `--dump-config`. Agent presets (`standard`, `minimal`, `ptc`, `cordis`) are directories holding one `agent.cordis.yml`. https://deepwiki.com/deepseek-ai/deepseek-harness/2.2-plugin-composition:-profiles-bundles-and-configuration · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/README.md

## 9. Error handling and recovery

**LLM retries (`llm-retry`).** Normal mode default: 5 retries for `EMPTY_RESPONSE`, `RATE_LIMIT`, `SERVER`, `TIMEOUT`, `TRANSPORT`; exponential backoff 500 ms → 10 s with 10 % jitter, honoring `Retry-After`; "always" mode retries every failure until success/cancel. Errors normalize to stable codes (`INVALID_CREDENTIAL`, `MISSING_CREDENTIAL`, `RATE_LIMIT`, `CONTEXT_WINDOW_EXCEEDED`, `QUOTA_EXCEEDED`); the DeepSeek adapter has an `idleWatchdog` that aborts when chunks stop arriving. Provider failures surface only as terminal `finish` chunks; middleware/consumer defects throw. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-retry/README.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.5-llm-adapters-and-streaming · https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.md

**Request errors in the loop.** Terminal failures enter `agent/request-error`; a listener may return `{ kind: 'retry' }` (without `next()`); unhandled failures terminate the turn. Overflow → compaction recovery (§3) with `maxOverflowRetries: 1`. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md

**Malformed tool input.** Schema-invalid arguments never reach the body and come back as an ordinary error result; unknown tools → `UNKNOWN_TOOL`; throws → `isError`; timeouts → `TOOL_TIMEOUT`; aborted before dispatch → `ABORTED_BEFORE_DISPATCH`. None of these end the turn. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md · https://deepwiki.com/deepseek-ai/deepseek-harness/3.2-tool-registry-and-execution-pipeline

**Stuck loops.** Repeat reminders at 3/5/8 (§8); there is no automatic escalation or hard stop — `Stop` hooks and `agent/turn-stopping` listeners are the extension point. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/guard/repeat-tool-reminder/README.md

**Escalation.** DSH has no cloud/bigger-model fallback. The nearest analogues: subagent `stopReason` mapping (non-`completed` → error-marked tool result), Ralph's `blocked` status, and goal `blocked` with a `round-limit` code. https://deepwiki.com/deepseek-ai/deepseek-harness/3.4-subagent-orchestration · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/goal/goal-round-driver/src/index.ts

**Defensive patterns worth naming.** Report orthogonal outcomes independently (`timedOut`, `signal`, `exitCode`); normalize on both sides of a public contract; async state is not synchronous state; dispose must reach quiescence; contain callback exceptions in the dispatcher; scrubbed env and `0700`/`wx`/`0o600` temp files. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.md

Test: the same recorded session reproduces the same step log. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/testing.md
26. **Hook contract.** Pre/post tool hooks as in-process functions with a decision enum merged deny > ask > allow, a hook may block with a model-visible reason or add context; `Stop` may force continuation. Goliath: `beforeStep`, `afterResult`, `beforeStop` hooks with the same merge rule. Test: two hooks returning `allow` and `deny` yield `deny`. https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills
27. **Read-before-write as a guard.** A write/edit on a path the session never observed returns `FS_NOT_OBSERVED` ("— read the file, then retry"); a changed file returns `FS_STALE_VERSION`. Goliath: any mutating tool over user data (notes, calendar) requires a prior read step of that record in the log. Test: `update_event` without a preceding `get_event` for the same id is refused with that message. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/fs/tool-fs/README.md

## 12. What does not transfer to a 4k on-device model, and why

1. **Full-history ReAct steps with no step cap.** DSH replays the whole derived history each step and explicitly has "no built-in turn budget." A 4,096-token window cannot hold history; Goliath's flat one-step plan plus a hard step cap is the correct inversion, not a simplification. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md
2. **Bulk compaction that replays the shadowed span to a summarizer.** The summarizer receives the same system prompt, all tool schemas, and the whole shadowed region, and may emit up to `maxTokens: 8192`. That is two windows of input and two of output on-device. The rolling per-step scribe is the only viable shape; keep DSH's _format rules_ (item 3), not its trigger. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/summarizer.ts
3. **`thresholdRatio 0.8` / `retainRatio 0.16`.** At 4,096 tokens that is compaction at 3,276 and a verbatim tail of 655 tokens — roughly one step. The ratios assume 128k+ windows; on-device, compact every step and size the retained tail in _steps_, not tokens. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/config-catalog.md
4. **Prefix-cache alignment as a design driver.** Reusing the live system prompt in the summarizer exists to keep the provider's warm prefix cache. Fresh-context workers via the AI SDK bridge get no exposed cross-request KV reuse; do not shape prompts around it. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/src/summarizer.ts
5. **Parallel tool calls (`maxParallelToolCalls: 10`, `isConcurrencySafe`).** One request in flight; sequential only. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md
6. **57 tools with full schemas in every request.** Even the standard preset's subset would consume most of the window; Goliath's one-tool-per-worker is required. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md
7. **Code mode (`run_code` / PTC) and the `workflow` JS orchestration tool.** They need a JS/Python runtime for model-written programs and a model that writes correct multi-call programs; a 3B guided-JSON model returning arguments cannot, and iOS has no subprocess sandbox for it. https://deepwiki.com/deepseek-ai/deepseek-harness/3.2-tool-registry-and-execution-pipeline
8. **Pruning sizes 8,192 / 4,096 / 1,024 chars.** ~1.2k tokens of a single pruned result is 30 % of the window. Scale by ~1/32 (item 9). https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-tool-result-pruner/README.md
9. **Spill recovery via `read --offset/--limit` or `grep` on a path.** Presumes a filesystem and a model that will come back for a second look; on-device the model rarely gets a second window and there is no grep. Borrow only the bounded preview + opaque locator. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/spill/spill-policy/README.md
10. **`AGENTS.md` chains with a 65,536-byte budget and 1 MiB per file.** ~16k tokens of instructions; Goliath's instruction budget is on the order of 150 tokens. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-presets/presets/standard/agent.cordis.yml · https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md
11. **Ralph `maxRounds: 256` / handoff 16,384 chars / goal `maxGoalRounds`.** Hundreds of on-device rounds are minutes of battery and latency; single-digit caps with escalation are the on-device equivalent. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/workflow/tool-ralph/README.md
12. **Subagent depth 3, continuable background children, ACP/Claude Code/Codex drivers, `fork` (inherit parent turns).** No process model on iOS, no second model to delegate to except the cloud fallback, and `fork` presumes a history worth inheriting. Goliath's workers are depth-1, single-shot. https://deepwiki.com/deepseek-ai/deepseek-harness/3.4-subagent-orchestration
13. **Hooks as shell subprocesses with 600,000 ms timeouts and `transcript_path`.** No subprocess on iOS; hooks must be in-process JS (item 26 keeps the contract, drops the transport). https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/hooks/hooks-codex/src/index.ts
14. **Landlock / bubblewrap / Windows restricted-token sandboxing and `SANDBOX_UNAVAILABLE`.** The iOS app sandbox already bounds the process; the approval _seam_ transfers (item 13), the OS mechanisms do not. https://deepwiki.com/deepseek-ai/deepseek-harness/4.3-sandboxing-and-security
15. **Network-shaped retry policy (`RATE_LIMIT`, `SERVER`, `TRANSPORT`, 500 ms → 10 s, `Retry-After`).** There is no network on the on-device path; only empty output and stalls exist, and every retry costs battery. https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-retry/README.md
16. **`reasoning_effort` / `reasoning-delta` chunks and streaming tool-call assembly.** The on-device model has no reasoning tokens and no logprobs; guided JSON arrives whole, so `BlockAssembler`-style delta parsing of tool calls is unnecessary (text streaming for UI still applies). https://deepwiki.com/deepseek-ai/deepseek-harness/3.5-llm-adapters-and-streaming
17. **Skill catalog at ≤ 500 chars per description, plus MCP eager registration.** Even the catalog would be hundreds of tokens; on-device keep ≤ 5 skills with ≤ 60-char descriptions or select skills outside the model. https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md · https://deepwiki.com/deepseek-ai/deepseek-harness/7.2-mcp-client-hooks-and-skills
18. **Repeat reminders that only _remind_ (3/5/8) and never stop.** DSH relies on a large model to change course; a 3B model that repeats once will usually repeat again. Keep the canonical key, cut the thresholds to 2 → remind, 3 → escalate (item 5). https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/guard/repeat-tool-reminder/README.md
19. **SQLite FTS5 session query, session forking with `seedLength`, `session_event_*` tools.** Useful for a desktop product; on-device the step log is small and escalation carries it whole. https://deepwiki.com/deepseek-ai/deepseek-harness/3.3-session-log-and-persistence
20. **100 % per-file coverage as the gate and Vitest partitioning.** A policy for a 14,918-commit monorepo, not a harness design point; Goliath's equivalent is the record/replay JSONL (item 25). https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/testing.md
